# 故障排查

先在“设置 → 诊断”查看公开状态码和建议操作，再决定是否重试。不要反复点击会创建网络请求的操作；持久 Job 会保留检查点，使用同一幂等键只会返回原任务。任何公开 issue 都不要提交凭据、私有 PDF、完整提示词、聊天、Cookie、启动秘密或包含用户名的绝对路径。

## 启动与存储

- 浏览器未打开：确认进程仍在运行，从启动窗口复制本次 `127.0.0.1` 地址。不要改成 `0.0.0.0`。
- `storage_unwritable`：在首次配置中选择当前用户可写且不位于 Git 仓库内的目录；不要用管理员模式掩盖权限问题。
- 单实例提示：回到已经打开的浏览器标签页；确认旧进程安全退出后再启动。
- 数据库迁移失败：停止写操作，保留自动迁移前快照，使用产品内恢复流程；不要手工修改 SQLite schema。

## Agent

- `configuration_invalid`：修复 Codex/Ollama 自身的配置或端点，再运行能力检测。paper-reader 不会改写工具配置。
- `service_not_running`：启动 Ollama Local，确认本机 API 可用后重试。
- `not_installed`、`not_authenticated`、`version_unsupported`、`probe_timeout`、`unavailable`：按 [配置指南](codex-ollama-setup.md) 的状态表处理。
- `credential_store_unavailable`：操作系统凭据库不可用；云端后端和需要密钥的来源保持禁用。不要把 key 临时写入配置文件或环境日志。

Agent 任务的持久错误分类同样是公开、脱敏的：`authentication` 表示本次调用认证失败；`timeout` 可在确认后重试；`cancelled` 表示用户取消；`output_limit` 需要缩小证据范围；`invalid_output` 表示结构化结果在一次修复后仍不合格；`protocol` 表示响应协议不兼容；`process` 表示本地子进程失败；`transport` 表示网络或本机 API 传输失败；`unavailable` 表示后端当前不可用。它们不会包含命令行、响应正文或凭据，失败草稿也不会覆盖正式结果。

### 关键词请求失败

`GET /api/v1/settings/agents` 返回 200 只说明能力检测请求完成。是否推理成功，要看随后 `agent invocation completed/failed` 中的实际模型、错误码和 token 数量。失败日志会显示 `error_code` 和安全的使用量，不记录研究意图、模型答案、思考正文或服务端错误原文。

| HTTP / code | 原因与操作 |
|---|---|
| 502 / `output_limit` | 思考或答案耗尽输出预算、输入超出上下文。关键词可先选择“最小”推理强度；长论文缩小证据范围。 |
| 502 / `invalid_output` | 最终答案未通过 JSON 结构、双语或关键词数量校验。重新生成或选择其他模型。 |
| 502 / `protocol` | 模型不存在或响应协议不兼容。重新检测模型并选择已发现的模型。 |
| 504 / `timeout` | 模型加载或生成超时。检查 Ollama 状态，尝试较小模型。 |
| 503 / `unavailable`、`transport` | 服务停止、模型加载失败或无法连接。检查本机服务；内存不足时选择较小模型。 |

如果 `eval_count` 已增长而 `content` 为空，模型可能正在思考。GPU/内存占用也可能来自加载和默认保留模型，不能单凭占用判断请求是否成功。可用 `ollama ps` 查看当前上下文和 CPU/GPU 分配；服务端最终完成事件与 token 计数才是本次调用的证据。

## 来源、PDF 与模型

### 部分成功但推荐为空

`GET /api/v1/plans`、`GET /api/v1/runs/.../recommendations` 返回 200 只表示页面读取成功。`partial_success` 表示有来源批次成功、有来源批次失败；成功批次也可能没有符合筛选条件的论文。

在空推荐页查看“为什么没有候选论文？”：每个月份/来源分别显示获取记录、日期内记录、关键词匹配，以及日期外、缺少更新时间和关键词不符的数量。缺少更新时间的记录不能通过日期筛选。多个必需概念组必须同时命中，同组关键词可以任意命中；只有标题与摘要通过已确认规则的记录才会入库。跨来源、跨查询的重复记录会合并，获取条数不等于唯一论文数。

- OpenReview `permanent_request` / HTTP 400：旧版使用不兼容的 `query` 参数。当前版本按 API v2 的 `terms` 参数轮流检索必需概念组，然后在本地应用完整日期与关键词条件。重启更新后的服务，回到关注计划点击“立即运行”。
- 获取大于 0、日期内为 0：来源返回的记录不在选定自然月内；可在新计划中扩大月份范围，再确认关键词和来源后检索。最近 2 个自然月包括本月，并非过去 60 天。
- 日期内大于 0、关键词匹配为 0：检查必需概念组是否过多、英文短语是否过窄。在新计划的关键词确认步骤补充常见英文同义词，将可选方法偏好移到加分组，然后明确确认。
- 已到扫描上限：本次仅扫描有界数量的来源结果，不能据此认定整个来源没有论文；可缩小研究主题或在新计划中调整候选配额。
- 历史运行显示 `—`：旧运行没有保存详细过滤数量，系统不会猜测或改写历史结果。重新运行计划后，新运行会保存过滤统计。

“重新评分”只评分已经入库的本次候选，不会重抓来源。零候选时该按钮不可用。修复来源后应重新运行计划；临时网络故障则使用“重试失败来源”从已有检查点继续。日志中的 `discovery batch succeeded/failed` 会记录来源、月份、获取/匹配数量、停止原因和公开错误码，不记录检索词或凭据。

- `source_rate_limited`：其他来源的部分成功结果会保留。等待来源给出的重试时间，再从失败月份批次继续，不要新建重复计划。
- 来源显示未配置：从官方渠道申请所需 key；免费的来源仍可正常运行。
- PDF 没有文本：先确认文件合法可读，再对扫描页按需下载 OCR 模型。OCR 结果会显示页码、坐标和置信度。
- 向量检索不可用：系统自动回退 FTS5 词法检索并降低置信度；可稍后在模型管理中下载并校验嵌入模型。
- 模型下载失败：检查剩余空间、官方地址、许可证与哈希；从任务抽屉续传，不要使用来历不明的模型文件。

## 安全诊断包

“导出安全诊断包”只收集版本、公开状态码、脱敏日志摘要、能力矩阵和失败任务分类，默认排除数据库、PDF、标注、报告、聊天、偏好、完整提示词、凭据和本地会话信息。导出后仍应人工打开清单检查，再通过安全报告渠道发送。安全问题按 [SECURITY.md](../SECURITY.md) 私下报告；普通使用问题按 [SUPPORT.md](../SUPPORT.md) 分流。

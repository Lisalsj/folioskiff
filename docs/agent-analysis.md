# Agent 分析与提示词

## 1. 后端

首版 `AgentBackend` 包含 Codex CLI、Ollama Local、Ollama Cloud。Codex 默认复用自身登录状态，不复制凭据、不修改 `~/.codex/config.toml`；执行使用稳定的 `codex exec`。Ollama Local 动态读取本机 API 模型，Cloud key 存入系统凭据库。模型发现失败时允许手填模型 ID，不硬编码型号。

默认推理强度：关键词 `medium`、单篇报告 `high`、论文聊天 `medium`、多篇比较 `high`。全局可配，单次可覆盖。

## 2. 关键词 Agent

研究意图只用于生成建议，不直接过滤论文。首轮生成约 12–24 个双语关键词，按必需、增强、排除概念组组织，可继续扩展且没有最终数量硬上限。每轮立即保存为不可变子版本和结构化差异；用户确认时另行追加不可变确认事实，未确认版本不能编译检索条件。

生产关键词接口按用户设置调用默认 Agent，使用 `AgentTaskKind.KEYWORDS`、父版本和有限的偏好上下文，并用 `KeywordSetDefinition` JSON Schema 验证输出。后端不可用、未登录、超时、模型缺失或输出非法时返回带 `code`、`message`、`backend_id` 的结构化错误；不会静默用本地规则冒充模型结果。本地规则仅作为显式手工离线模式，并在 `generator_info` 标明来源。

当前 `KeywordSuggestionBackend` 是异步替换接口，接收研究意图、父版本、目标首轮词数、本地语料词和偏好词；输出仍需经过统一 Pydantic 结构验证。`generator_info` 保存调用模式、任务类型、后端、请求模型、实际模型、推理强度和脱敏使用量摘要。陌生意图既不命中受控词表、又没有足够双语本地证据时返回“需要手工配置”，严禁直接把整句研究意图变成过滤条件。

关键词页会动态读取 `/api/v1/settings/agents`，可在每次点击前选择 Codex CLI、Ollama Local 或 Ollama Cloud、具体模型和推理强度。Ollama 未指定模型时明确显示“自动选择第一个已发现模型”。本地关键词请求在“最小”强度使用 `num_ctx=16384`、`num_predict=2048`，其他强度使用 `num_ctx=32768`、`num_predict=16384`，为共用输出额度的思考和答案保留空间。支持思考的 Ollama 流会把 `message.thinking` 作为 reasoning 片段处理，再把 `message.content` 作为结构化答案；两部分均不会被写入凭据或诊断日志。

## 2.1 模型调用审计

所有生成调用集中经过 `AgentBackendRegistry.generate()`；页面加载、Agent 能力探测、模型列表发现和分析预检只读取能力或构造请求，不调用 `generate()`。

| 用户动作 | 服务入口 | `AgentTaskKind` | 是否生成 |
| --- | --- | --- | --- |
| 生成研究关键词 | `discovery/api.py` → `AgentKeywordSuggestionBackend` | `KEYWORDS` | 点击按钮后调用 |
| 生成论文报告 | `agents/analysis_service.py` | `REPORT` | 点击分析并通过预检后调用 |
| 论文聊天/解释 | `assistant/service.py` | `ASSISTANT_ASK` / `ASSISTANT_EXPLAIN` | 发送消息后调用 |
| 论文翻译 | `translations/service.py` | `ASSISTANT_TRANSLATE` | 开始或继续翻译后调用 |
| 多论文比较 | `agents/comparison_service.py` | `COMPARISON` | 点击生成报告并通过预检后调用 |
| 相关推荐意图 | `related_resources/intent.py` | `RELATED_INTENT` | 点击精炼后调用 |
| 外部知识资源 | `related_resources/web_research.py` | `RELATED_EXTERNAL` | 明确同意联网并启动后调用 |
| 语义检索、OCR、模型资产下载 | 向量/OCR/资产服务 | 不属于 Agent 任务 | 使用专用本地模型，不生成 Agent 文本 |

每次实际调用只记录任务类型、后端、请求/实际模型和安全用量摘要；失败会记录分类错误码。模型发现或预检成功不能被当作推理证据，只有生成请求返回结构化结果后，响应中的 `generator_info` 和任务审计才显示实际调用。

## 3. 分析触发与预检

任何模型调用必须由用户点击“分析”或明确发送聊天消息触发。分析前显示后端、模型、推理强度、语言、模板、全文/摘要证据等级、联网开关和范围。云端后端持续可见；Codex 默认只分析所选论文，外部网络研究需单独开启。Ollama 报告不提供联网研究。

Codex 每次使用新只读隔离目录，只放所选文档版本、标注和必要元数据。正文视为不可信证据，正文中的提示指令不得改变系统任务、访问范围或工具权限。

### 3.1 点击触发的持久分析任务

`POST /api/v1/analysis/works/{work_id}/preflight` 是只读预检：它可以探测后端与模型、构造证据和组合提示词，但既不创建 Job，也不调用模型。响应包含全文/摘要证据等级、覆盖度、后端位置与云端标识、可选模型、是否允许手填模型 ID、推理强度、service tier、语言、模板、联网范围、警告以及本次请求指纹。打开论文、PDF、批注、评分、报告列表或应用本身同样不会创建新的分析请求。

只有受本地会话、Origin、CSRF 和 `Idempotency-Key` 保护的 `POST /api/v1/analysis/works/{work_id}/reports` 才能创建 `analysis.report` Job，并立即以 HTTP 202 返回。命令必须回传当前预检指纹；证据、设置或提示词在预检后发生变化时返回 409，不能用旧预检启动分析。相同幂等键与相同请求复用原 Job，即使其后本地证据改变也不会偷偷改写已冻结任务；同一键绑定其他请求则冲突。

Job 冻结确切证据包、完整组合提示词、后端/模型、推理参数、模板、语言和网络策略。worker 在模型调用前重新校验证据 SHA-256、提示词 SHA-256、请求指纹、安装/认证状态和后端能力；任一不一致都会形成脱敏失败草稿，且模型调用次数保持为零。流式片段先写入 `analysis_report_fragments`，再发布 Job 事件；进程中断后的新尝试从旧片段末尾继续追加序号，不改写既有诊断。应用重启只恢复已经由显式命令创建且仍为 queued/running 的任务，不会凭空启动分析。

成功任务只把独立的 `LibraryState.analysis_state` 设为 `available`，并追加白名单内的 `analysis_report_generated` 偏好事件；收藏、喜欢/不喜欢、置顶、阅读进度、评分快照和推荐排序均保持不变。失败或取消不覆盖旧正式报告。正式报告可读取确切 Markdown、下载自包含且已转义的 HTML，或打开打印版 HTML 交给浏览器生成 PDF；服务端不伪造 PDF 文件。所有分析响应均为 `private, no-store`，HTML 另有禁止外部资源、表单、基址和嵌入的 CSP。

## 4. 提示词与报告

内置通用、ML/AI、生物医学三套版本化模板；用户可保存全局模板或添加单篇临时指令。正式报告固定结构至少包含：

- 研究问题与贡献；方法与关键假设；数据和实验；主要结果；限制与风险；复现清单；与用户研究意图的关系。
- 作者主张与 Agent 判断分栏；每个判断引用页码、图、表或外部来源。
- 文档哈希、证据等级、模型、推理强度、完整组合提示词、语言、时间和外部引用。

Codex 使用结构化输出约束；Ollama Local 在支持时传 schema；Ollama Cloud 进行解析、验证和一次修复重试。仍失败时保存诊断草稿，不生成正式报告。普通报告导出 Markdown、HTML 和浏览器打印 PDF。

视觉证据采用保守、失败关闭的路径：只有冻结页文本明确引用 Figure/图、Table/表、Equation/Eq./公式/方程，且文本不足以独立表达、后端与已探测模型均明确支持视觉、用户未关闭视觉证据时，才选择引用页及最多一页相邻上下文。候选和实际渲染都不超过 6 页；PyMuPDF 在内存中生成受像素、单页字节与总字节上限约束的 RGB PNG，不产生持久临时图片。每个文件名编码冻结 PDF SHA-256 前缀与页码，执行前再次核验内容寻址对象、文档身份和完整文件哈希。Codex 只通过 `codex exec --image` 接收这些图片；Ollama 只在首条相关 user message 的 `images` 字段接收 Base64，修复消息和其他请求字段不携带图片。模型能力未知、纯文本已足够、策略关闭、摘要回退、哈希冲突或取消时不会发送图片。

### 4.1 模板版本与默认设置

`0019_agent_templates` 建立三个开箱即用的中文模板版本：通用模板强调主张、证据、局限与适用边界，ML/AI 模板补充基线、公平比较、消融、效率与复现检查，生物医学模板补充研究设计、PICO/PECO、偏倚、效应量、临床意义与安全性。内置与用户模板均为不可变版本；所谓“编辑”会创建带父版本 ID、递增版本号和正文 SHA-256 的 `custom` 子版本，旧报告引用的模板不会变化。

`agent_settings` 只保存默认后端、四类任务的动态模型 ID、推理强度、service tier、报告语言与默认联网开关。API key、Codex 登录材料和 Ollama Cloud key 不进入该表。默认值分别为 Codex、关键词 `medium`、报告 `high`、聊天 `medium`、比较 `high`、`flex` 和中文报告。

### 4.2 确切证据包与组合顺序

分析预检先从规范 Work 解析用户选中的 DocumentVersion，再生成当前 `agent-evidence-v2` 证据包；历史 `agent-evidence-v1` 只读保留。只有合法访问、PDF、文本提取完成、内容寻址对象存在且重新计算的文件 SHA-256 与版本完全一致时，证据等级才是 `full_text`。扫描页优先使用已完成 OCR，并保留页码、页面尺寸、来源、OCR 置信度和原始页文本哈希；普通页使用原生文本。v2 额外冻结显式页码/标注过滤器及选区坐标、上下文和验证状态，所有字段共同进入证据哈希。标注必须仍绑定同一文档哈希，否则预检失败关闭。字符预算截断、缺 OCR 页和其他覆盖缺口均进入显式 warning/coverage，不能静默省略。

证据包不包含绝对路径、相对存储路径或凭据。其 SHA-256 覆盖规范 Work 元数据、选定文档公开身份、实际提供的页文本、标注、覆盖度、警告和本次研究意图；正文、页面、标注或研究意图任一变化都会形成新证据身份。全文不可用或没有可用页时，只能使用非空 Work 摘要并标为 `abstract_only`；连摘要也没有则在调用模型前拒绝。

最终提示词按固定顺序组合：不可变安全契约、任务契约、所选模板、Work 元数据、不可信论文证据、可选的视觉候选清单、可选单次指令、输出 JSON Schema。论文正文、元数据、标注、历史消息、用户问题、比较中间结果与模型输出都以确定性 JSON 放入数据区，并把 `<`、`>`、`&` 等结构分隔符编码；其中出现的角色声明、命令、凭据请求、MCP/插件请求、联网请求或评分修改要求始终只是数据。组合提示词另有 SHA-256，并与模板版本 ID 和证据 SHA-256 一起留给正式报告复现；安全契约明确禁止 Agent 修改论文评分、排序、偏好或用户反馈。

### 4.3 结构化报告、引用与失败语义

`analysis-report-v1` 禁止未知字段，并固定为标题、概览、研究问题、作者主张、核心贡献、方法、关键假设、数据与实验、主要发现、局限与风险、可复现性、与研究意图的关系、Agent 判断。作者主张和 Agent 判断是两个不能混写的字段；每条陈述至少包含一个类型化引用。

本地引用分为摘要、页、图、表、公式和标注。页、图、表、公式必须引用当前证据包中真实存在的 `evidence_id` 和一致页码，图/表/公式还必须给出标签；标注必须命中同一证据包中的精确标注 ID。摘要引用只允许固定 ID `abstract:work` 且证据包确实包含摘要。外部引用必须具有独立 `external:*` ID、标题和无凭据 HTTPS URL，并且本次请求明确启用了外部研究。任何越出证据清单或网络策略的引用都不能形成正式报告。

Markdown 由受控渲染器按固定段落顺序生成，不接受模型自带 Markdown/HTML 结构。模型文本中的 HTML 和 Markdown 控制字符会转义；外部引文清单从已验证引用确定性去重。相同结构化内容必然生成相同 Markdown 和报告 SHA-256。

`0020_analysis_reports` 把生成生命周期拆成三个只追加事实：`analysis_report_fragments` 按从 0 连续的序列先落盘，随后才允许流式发送；`analysis_reports` 只接收已通过 schema 与证据交叉验证的正式版本；`analysis_failure_drafts` 保存脱敏、限长的错误、原始响应诊断、验证错误和 0/1 次修复计数。一次 Job 只能产生正式报告或失败草稿之一，三表均由数据库触发器禁止更新和删除。失败不会覆盖同一 Work 的任何旧正式报告。

正式版本冻结 Work/文档 ID 与内容哈希、完整证据清单与证据 SHA-256、后端、请求/实际模型、推理强度、service tier、语言、模板版本、完整组合提示词与哈希、网络策略、结构化 JSON、受控 Markdown、外部引文、schema 版本和请求指纹。相同 Job 的完全相同重试幂等复用；任一来源不同则作为冲突拒绝，不能偷偷改写原版本。

## 5. 聊天与比较

每个规范 Work 只有一个持久 Assistant 会话。规范接口为只读的 `GET /api/v1/assistant/works/{work_id}` 与显式命令 `POST /api/v1/assistant/works/{work_id}/tasks`；只读操作在没有历史时返回空值，不创建 Job、不调用模型。只有用户明确发送非空问题后，受会话、Origin、CSRF 和 `Idempotency-Key` 保护的任务命令才创建 `assistant.reply` Job 并返回 HTTP 202。首条用户消息、所选文档版本、内容/证据哈希、后端和请求模型与 Job 在同一事务中先提交，因此客户端收到 202 时问题已经可恢复。一个会话已有 queued/running 回复时拒绝第二个并行回复，相同幂等请求复用原 Job。四个 `/api/v1/conversations` 操作仅是带 OpenAPI 兼容标记的无存储投影，不构成第二套领域模型。

用户、Assistant 与系统诊断消息按单调序号只追加；每条消息各自冻结文档版本、内容 SHA-256、证据清单、后端/请求与实际模型、用量、引用和时间。切换论文版本或后端不会伪装成同一次证据，也不会改写旧消息。Assistant 只能引用本次证据包中真实存在的摘要、页、图、表、公式或标注；论文聊天不接受外部研究引用。流式片段先写入 `assistant_fragments`，再发布可恢复 Job 事件，断线后可从已持久化片段和事件序列继续。

接近上下文预算时，系统创建可查看的本地提取式检查点。检查点保存覆盖的消息范围、摘要哈希和保守字符/令牌估计；组合提示词使用最新检查点加其后的原始消息，并动态为最新完整消息保留预算。原始消息始终保留，数据库触发器禁止更新或删除消息、片段与检查点。后端失败或取消只追加独立诊断消息并终结 Job，先前用户问题、Assistant 回复、正式分析报告、评分和反馈均不改变。

阅读工作台的聊天标签与报告标签分别保持挂载和滚动位置。打开标签仍然不调用模型；用户可选择动态发现或手填的模型、切换 Codex/Ollama 和聊天推理强度，运行时可查看已保存片段、取消任务并在重载后恢复。当前/旧文档版本在每条消息上持续可见，页码引用可直接返回 PDF，移动端同时保留阅读位置。

### 5.1 显式多论文比较

多论文比较从本地论文库按用户顺序选择 2–50 个不同的规范 Work。合并别名在预检时解析到规范身份；同一规范 Work 被重复选择立即冲突，不能以两个别名伪装成两篇论文。`POST /api/v1/comparisons/preflight` 只冻结候选顺序、确切文档/内容/证据哈希、逐篇证据等级与覆盖度，并探测后端和模型；它不创建 Job、不调用模型。缺少全文会明确使用摘要证据，完全没有合法证据的论文保留在预检清单中并计为 0 覆盖；只要仍有至少两篇可用论文即可继续，遗漏项不会被冒充为低质量论文。

只有用户点击“生成比较报告”后，带本地会话、Origin、CSRF、`Idempotency-Key` 和当前预检指纹的 `POST /api/v1/comparisons/reports` 才创建 `comparison.generate` Job 并返回 HTTP 202。2–10 篇可用论文只发起一次直接结构化综合；11 篇以上先为每篇论文生成并验证 `comparison-paper-evidence-v1`，再以每批最多 10 篇形成有界综合，最后在存在多个批次时进行一次总综合。所有调用使用 `AgentTaskKind.COMPARISON`、比较任务默认 `high` 推理和关闭外部研究的证据边界。

逐篇提取成功或失败都形成只追加检查点，并记录请求模型、实际解析模型与 service tier。新 Job 重试时只可按证据哈希、后端、显式请求模型、推理强度、service tier 和提取提示词哈希复用已验证成功项；未指定模型时不跨 Job 复用，失败项可以重新尝试。每个正式 `comparison-report-v1` 冻结用户顺序、Work/DocumentVersion/内容/证据哈希、逐篇提取状态、逐篇与总体覆盖度、后端/请求与实际模型、推理参数、最终完整提示词、批次数、结构化内容、受控 Markdown、请求指纹和报告哈希。失败或取消不删除逐篇检查点，也不覆盖旧版本。

比较引用额外携带 `work_id`，再与该 Work 的确切本地证据清单交叉验证，避免不同论文相同 `page:1:native` ID 发生串证。正式 Markdown 由固定渲染器生成，模型文本中的 HTML/Markdown 控制符会转义。比较历史、详情、片段、逐篇提取状态和 Markdown 导出全部是 `private, no-store` 响应。

比较服务没有写入单篇 `AnalysisReport`、`ScoreSnapshot`、`LibraryState`、偏好事件或 Assistant 会话的代码路径。直接/分阶段成功、模型失败、重试和后端切换均不能改变单篇评分、排序、反馈、报告或聊天。

### 5.2 证据绑定翻译与双语成果

翻译是独立的 `translate` Agent 任务，不是聊天消息、正式分析报告或评分维度。用户可从已验证 PDF 选区、当前页、当前章节或全文启动；命令固定 `local_only`，正文与术语都作为不可信 JSON 数据传入。切换到翻译模式、打开双语页、切换对照模式或修改 URL 都不能调用模型，只有显式“开始翻译”或“继续翻译”才创建或恢复持久 Job。

每份译文绑定规范 Work、文档版本及内容 SHA-256、Assistant 上下文快照、源/目标语言、提示词版本和不可变 segment ID。前端通过 `/api/v1/translations` 读取成果与段落，并从全局 Job 事实恢复进度；成功段落、部分失败诊断、OCR 置信度和页范围不会因刷新而丢失。术语变更只允许在后端声明可变的成果状态中进行，并把真正受影响的段落标为 `stale`；重新生成必须由用户显式继续，已完成成果保持不可变。

双语阅读路由为 `/library/:workId/translations/:artifactId`。页面按 PDF 页分页渲染，对照、原文、译文模式及当前页/段落保存在 URL 查询中；Markdown、HTML 和打印继续使用服务端内容寻址导出。选区翻译成功后可由用户点击“用作后续提问上下文”写入可见草稿，但不会静默发送，也不会改变论文聊天、正式报告、评分、排序或偏好。

### 5.3 相关推荐检索意图

首次草案完全在本地生成：服务端重新核验现有 Assistant 上下文快照、页面文本哈希、Work/文档身份，再从标题、摘要、用户明确选择的页/章节/选区、来源关键词、已确认计划词和受控双语词表组成 6–20 个词的必需组与增强词。该步骤不探测模型、不调用连接器或网络，草案在确认前不能形成检索命令。

只有用户显式点击精炼才发送 `RELATED_INTENT` 请求。请求固定 `external_research=false`，模型只能在当前草案已有来源 ID 内删减；论文证据、当前草案和用户指令分别以转义 JSON 放入不可信区段，模型只允许返回符合封闭 schema 的意图提案。成功结果保存新修订、逐词增加/删除/移动、来源和时间范围差异，以及后端/模型与提示/响应哈希；不保存原始模型输出。结构无效、证据哈希变化或并发修订冲突均不发布新修订。

确认由服务端写入带时区时间并要求当前修订号。重复确认相同内容幂等；编辑未确认草案可在一次显式确认中形成新修订并确认，编辑已确认内容则先回到新未确认修订，必须再次确认。进入 queued、running 或终态后，当前修订及历史不能再通过意图仓储重写。

### 5.4 外部知识资源研究

外部网站与学术连接器是两条独立路径。只有当前意图已确认、对应集合明确保存 `include_external_web=true` 与 `external_web_consent=true`，并且所选后端同时可用、支持封闭 schema 和外部研究时，才构造 `RELATED_EXTERNAL + external_research=true` 请求；Ollama 等不具备该能力的后端在模型调用前关闭失败。上下文快照、文档内容哈希、证据哈希或意图修订不一致时同样保持零生成调用。

提示词把当前意图和论文证据作为转义后的不可信 JSON，只要求 Agent 返回最多 36 个标题、HTTPS URL、类型、理由和发布者提案。提案不是验证事实：应用逐项执行独立 URL/DNS/TLS/HTTP 校验、来源质量检查与去重，最终最多保留 12 个已验证资源；其余结果记录稳定拒绝码或截断事实。正式结果保存请求/实际模型、推理强度、服务等级、完成时间以及提示词和原始输出 SHA-256，不保存原始模型输出、网页正文、凭据或本地路径。

## 6. 不可破坏约束

Ollama 所有生成路径共用模型自动选择、按模型能力映射思考控制、任务级上下文/输出预算、总时间限制和流式错误分类。关键词对结构错误和服务错误返回不同的 HTTP 状态；额度耗尽不会重复同参数请求，Cloud 的结构修复由后端负责，关键词适配层不会再叠加一次同类重试。调用日志包括安全错误码和 token 计数，禁止记录提示词、思考内容或原始服务错误。

报告、聊天和评分相互独立；Agent 失败或切换后端不得更改评分、排序、反馈或已有正式报告。摘要回退必须醒目标注，且不能声称看过全文。

## 7. 本地只读 smoke 与 v0.5 验收

真实后端 smoke 默认只探测本机能力，不生成内容，也不进入 CI。Windows 开发者可在已自行安装并登录 Codex、或已启动 Ollama 后执行：

```powershell
codex --version
codex mcp list --json
Invoke-RestMethod http://127.0.0.1:11434/api/tags
```

随后启动应用，导入一份可公开使用的 PDF，打开“分析前预检”并核对后端位置、动态模型、全文/摘要等级、视觉页数和联网关闭状态；关闭预检应保持零生成调用。若要继续做真实生成 smoke，必须由测试者本人点击按钮，并预先了解所选 Codex/Ollama Cloud 账户可能产生的用量；只使用公开夹具、只读沙箱和关闭外部研究。不得把真实云端生成、凭据或个人论文加入自动化 CI。

自动验收使用完全本地的假后端，覆盖成功报告、失败草稿不覆盖旧报告、第二版本、Markdown/HTML/打印入口、聊天刷新恢复、可见压缩检查点、2–10 篇直接比较、11 篇以上分阶段比较、桌面/移动标签和 axe。数据库验收在同一真实 SQLite 中预置非空 `score_snapshots` 与 `run_candidates`，分别经过成功和失败分析后比较完整查询字节，确保两表逐字节不变。

## 8. v2 统一阅读 Assistant

统一 Assistant 把提问、解释、翻译和相关资源意图写入同一 Work 会话，但为任务保留独立类型、输入哈希和证据范围。翻译默认是**英文到简体中文**，结果保留公式、引用和段落映射；普通提问、解释和翻译的 `network_policy` 固定为 `local_only`。

相关推荐先由本地论文证据产生可修改检索意图，用户确认后才访问启用的学术来源。一般知识网站查询属于 `external_research`，必须逐次显式授权并记录外部引用。论文内容和模型输出不能改变 `network_policy`，不能触发工具，也不能写评分、排序、反馈或既有正式报告。

# 推荐、评分与偏好

## 1. 四个独立指标

每篇论文显示 0–100 的 `relevance_score`、`quality_score`、`confidence` 和 `coverage`。覆盖度描述证据是否齐全，置信度描述结论是否可靠；缺失数据不能直接转成低质量。

默认综合排序：相关性 40%、客观质量 40%、新鲜度 10%、个性化偏好 10%。固定历史月份不使用新鲜度，其 10% 平均分配给相关性和质量。另提供最相关、最高质量、最新、最符合偏好视图。

`composite-v1` 对四个已经规范成 0–100 的信号做固定加权，不因某一信号证据不足而偷偷改变排序权重；证据不足已在各信号自己的分数、覆盖度与置信度中表达。综合覆盖度和置信度使用相同有效权重汇总，最后再应用论文完整性置信度上限。固定历史月份的有效权重为相关性 45%、质量 45%、新鲜度 0、偏好 10%，新鲜度组件仍保留但明确标记未参与。

五种视图共享同一冻结候选与综合快照，只改变第一排序键：综合、相关性、质量、更新时间或偏好分。后续依次使用综合分、其他主要分、更新时间和 Work ID 打破同分；缺失更新时间排在有时间记录之后。默认视图在排序前移除关键词不合格、撤稿或完整性冲突论文；用户明确查看被排除论文时仍保留原因和强警告。

## 2. 相关性

| 维度 | 权重 |
|---|---:|
| BM25/词法匹配 | 40% |
| multilingual-e5-small 语义相似度 | 40% |
| 已确认关键词与布尔规则 | 20% |

FTS5 是必需底座；FastEmbed/ONNX 的 E5 按需下载。向量扩展或模型不可用时，剩余维度重新归一化，但必须降低覆盖度和置信度并显示降级原因。

相关性规则版本为 `relevance-v1`。每个维度分别记录 `observed`、`unknown` 或 `not_applicable`：`unknown` 不参与得分并按原配置权重降低覆盖度，`not_applicable` 从适用分母移除而不处罚覆盖度。已观测维度按剩余权重重新归一；置信度为“覆盖度 × 已观测证据可靠度”。三项均未知时返回 0 分、0 覆盖度和 0 置信度，不制造中性高分或虚假确定性。

关键词证据按已确认概念组计算。必需组全部命中且排除组不命中才具有推荐资格；存在增强组时，必需组贡献 70%、增强组命中比例贡献 30%，否则必需组贡献 100%。保存命中的概念组与具体词，不把研究意图原文偷偷加入评分。

词法索引由 `0007_recommendation_fts` 建立，属于可重建派生数据，不改变规范 Work。`multilingual-v1` 先做 NFKC 与大小写归一：拉丁文字和数字按词索引，中日韩统一表意文字同时生成单字与重叠双字词元。查询按去重词元取并集，BM25 固定使用题名 5、作者 2、摘要 1 的字段权重，同分按 Work ID 排序；解释字段优先使用多字符词元，避免仅凭中文单字重合制造“摘要命中”。实现遵循 [SQLite FTS5 官方 BM25 与字段权重语义](https://www.sqlite.org/fts5.html#the_bm25_function)。

来源入库和人工合并后立即增量同步索引。应用启动时比较活动 Work 与索引记录数，发现中断写入会重建；因此 FTS 表不进入业务事实或备份一致性的权威边界。

语义模型固定为 `intfloat/multilingual-e5-small` 的提交 `0e60b8d9…`，384 维、均值池化和归一化；模型、分词器与配置共 492,421,556 字节，每个文件均记录 SHA-256。查询和论文分别添加 E5 要求的 `query:`/`passage:` 前缀。模型不随安装包分发，只有所有资产存在且哈希一致时才允许启用。

向量保存在缓存目录的独立 sqlite-vec 数据库，不进入规范业务库；Work ID、模型版本和内容哈希用于幂等增量更新。sqlite-vec 使用余弦距离，结果稳定映射到 0–100 语义分。FastEmbed/ONNX 与 sqlite-vec 的原生能力在隔离子进程中探测，原生 DLL 崩溃只产生降级原因，不影响主应用或词法检索。[FastEmbed 官方自定义模型示例](https://github.com/qdrant/fastembed#dense-text-embeddings)、[sqlite-vec Python 接入](https://alexgarcia.xyz/sqlite-vec/python.html)。

每次运行只评分 `RunCandidate` 记录的实际接受论文，不把全局索引中的其他论文混入结果。查询由该运行冻结的 `KeywordSetVersion` 按“必需组 → 增强组”的原顺序组合并去重，研究意图原文和排除词不进入召回查询；排除组仍在关键词资格判定中生效。词法无命中是可观测的 0 分，语义模型或原生运行时不可用则是 `unknown`。语义同步或候选距离计算任一步异常时，本次语义证据整体丢弃并降级，避免用半批结果产生不可比较的分数。

## 3. 客观质量

| 维度 | 权重 | 主要证据 |
|---|---:|---|
| 领域/年份归一化引用 | 25% | OpenAlex 百分位、FWCI；S2 可交叉验证 |
| 发表场所与评级 | 15% | CCF、用户导入 JCR/CAS/新锐榜单 |
| 作者公开学术影响 | 10% | 来源明确的作者指标 |
| 机构/实验室/企业影响 | 10% | 规范机构映射与版本化规则 |
| 代码和数据影响 | 20% | 明确关联的 GitHub/Hugging Face 证据 |
| 研究透明度 | 10% | 代码、数据、注册、可复现实验信息 |
| 发表成熟度 | 10% | 预印本、会议、期刊和版本状态 |

OpenAlex 是主要归一化来源且缺 key 不阻断基础推荐。CCF 内置 2022 第六版并记录版本；CAS 2025 最终版、JCR、新锐榜单只能由用户合法导入 CSV/XLSX，分别标识，不抓取、不混合伪造。期刊场所可用证据默认按 34/33/33 分配；CCF 只适用于计算机领域。

内置 CCF 数据标识为 `ccf-2022-sixth-2024-rename`：它来自 CCF 在 2023-03-08 正式发布的 2022 第六版，以及 2024-06-28 只修改四个会议名称的更名版；更名没有被误记为新评级版。[CCF 第六版发布说明](https://www.ccf.org.cn/Academic_Evaluation/By_category/2023-03-08/787209.shtml)、[CCF 2024 更名说明与文件](https://www.ccf.org.cn/Academic_Evaluation/By_category/2024-06-28/825349.shtml)。内置 649 条记录（284 期刊、365 会议），记录官方 PDF SHA-256 `9390786c…3913bca` 与逐条页码。当前名、全名和四项官方旧名只做 NFKC/大小写/标点归一后的精确匹配；`FSE` 这类自身有歧义的简称不会被猜测性绑定。产品映射 `ccf-abc-v1` 将 A/B/C 转为 100/75/50，证据可靠度设为 80；CCF 自身也明确提示目录不应成为单篇论文评价的唯一依据，因此它只构成可解释的场所证据。

本地目录导入要求用户勾选合法使用确认，并填写目录名、版本与来源说明。支持 UTF-8/GB18030 CSV 和 XLSX，标准列为 `venue`、`rating`、可选 `score`、`aliases`、`issn`、`eissn`；也接受对应中文列名。JCR 默认映射 Q1/Q2/Q3/Q4 = 100/75/50/25，CAS 一至四区使用相同等距映射，新锐 A/B/C/D 同理；用户文件中的显式 0–100 `score` 可表达其他合法榜单。重复场所或别名、未知等级且无显式分数、公式、越界分数、超过 10 MiB 或 20,000 行的文件会被拒绝。JCR、CAS、新锐各自拥有独立文件哈希、版本和活动指针；历史内容不可更新或删除，只能停用或导入新版本。

期刊命中证据按 JCR 34%、CAS 33%、新锐 33% 组合；只在已命中的来源间重归一，同时把原始可用权重作为置信度。例如缺少新锐证据时，JCR/CAS 得分不会被补零，但置信度降为 67。计算机会议使用 CCF；计算机期刊仅在没有本地目录命中时回退到 CCF。非计算机领域不套用 CCF。任何目录未命中都表示未知，而不是零分或低质量。

`quality-v1` 固定使用上述七维权重。`unknown` 维度保留配置权重并填入 50 分中性先验，但组件同时保存 `observed_value = null` 与独立 `imputed_value`，因此不会伪装成真实证据；覆盖度按已观测权重计算，置信度为“覆盖度 × 已观测证据可靠度”。`not_applicable` 维度从适用分母移除，不降低覆盖度。全部未知时质量分为中性 50、覆盖度和置信度均为 0；不存在任何适用维度时拒绝生成评分。

代码、模型与数据影响使用子规则 `artifact-impact-v1`。GitHub 仓库和 Hugging Face 模型/数据集先被规范成精确资源身份；星标、活跃度、下载或点赞等指标只有在同一身份具有论文正文、来源记录、出版者元数据、用户确认或 Crossref 明确关系证据时才可计分。名称相似、Agent 报告中的 URL、其他仓库的高热度和未被论文主体声明的关系全部忽略；没有明确链接时该维度为 `unknown` 并使用质量层中性先验，而不是把热度补给论文。当前自动提取仅接受 Crossref 中论文主体声明的 `is-supplemented-by`/`references` URI，且只识别规范 HTTPS GitHub/Hugging Face 地址；公式对命中的产物影响分取均值并保存被忽略指标。Crossref 官方建议用 `isSupplementedBy` 或 `references` 建立论文与数据/软件的明确关系。[Crossref 数据与软件引用指南](https://www.crossref.org/documentation/reference-linking/data-and-software-citation-deposit-guide/)

`ScoreSnapshot` 将规则版本、组件、配置/有效权重、中性缺失策略、证据观察 ID、硬约束及最终三项数值一起做规范 JSON SHA-256。相同内容重复计算复用原快照；数据库层禁止更新与删除，规则或证据改变只能追加新版本。

客观质量规则编辑器允许逐项启用/停用七个内置维度并重新分配总计 100% 的权重。每次保存生成新的 `quality-v1:<规则哈希>` 不可变修订，旧快照继续引用当时的规则版本和权重；恢复默认只切换活动规则，不删除自定义历史。停用维度不是“未知”，其配置权重明确为零；界面不能增加一个没有 `ScoreDimension` 实现与证据契约的任意因子。

分数证据面板直接渲染服务端返回的 score、coverage、confidence、逐维观测值/中性填充值、配置/有效权重、缺失策略和规则版本，浏览器不重算公式。`GET /api/v1/scores/works/{work_id}/snapshots/{score_type}?context_key=…` 返回冻结快照；规则设置页同时用全未知金样展示“质量 50、覆盖 0、置信 0”，帮助用户理解未知不等于低质量。

内置增强器只访问官方接口，并把规范字段与来源路径分开保存。OpenAlex 通过 DOI 单篇查询，读取 `cited_by_count`、`fwci`、`citation_normalized_percentile`、撤稿、场所、作者机构和主题；按当前官方政策必须配置免费 key，缺失时只禁用该增强器，不影响发现和词法推荐。[OpenAlex 单篇 Work 字段](https://developers.openalex.org/api-reference/works/get-a-single-work)、[OpenAlex 认证与额度](https://developers.openalex.org/guides/authentication)。Semantic Scholar Graph API 使用 DOI，缺 DOI 时可使用 arXiv ID；key 可选，但配置独立 key 时仍按官方初始 1 RPS 节流，主要用于引用量、影响力引用和场所交叉验证。[Semantic Scholar API](https://api.semanticscholar.org/api-docs/)、[Semantic Scholar 限速建议](https://www.semanticscholar.org/product/api/tutorial)。Crossref 使用 DOI 单条接口；配置联系邮箱后携带 `mailto` 与可识别 User-Agent 进入 polite pool，保存引用数、场所、许可证、基金和版本/更新关系。[Crossref 认证](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/)、[Crossref 2025-12 起限速](https://www.crossref.org/blog/announcing-changes-to-rest-api-rate-limits/)。

增强器不会用题名模糊结果静默绑定 Work。无受支持稳定标识时不发请求并记录不适用；404 与禁用状态也和网络失败分开。成功结果记录增强器/协议版本、匹配方式、规范字段、逐字段来源路径、抓取时间、规范响应 SHA-256，以及服务端返回的限额/剩余额度/重置窗口。API key 和联系信息不进入结果、哈希或错误文本。

`0009_metadata_observations` 将上述结果保存为只追加观察。完全相同的任务结果重试不会重复写入，新的抓取时间或字段变化会形成历史记录；读取质量证据时按增强器选择最新观察。Work 人工合并会迁移观察并按增强器与观察哈希去重，因此来源证据不会遗失，也不会因身份合并被重复计权。

`POST /api/v1/scores/runs/{run_id}/metadata` 将某次已结束发现运行的候选集与增强器版本冻结为持久 Job，并按“Work × 增强器”逐项写入 checkpoint。每项成功后立即保存观察；限流/网络失败只形成结构化、可重试失败，不回滚其他来源。重复幂等键返回原 Job；应用重启恢复中断任务；部分成功任务通过专用重试命令只补失败项。任务事件进入全局抽屉，取消在下一次网络调用前生效。`GET /api/v1/scores/works/{work_id}/metadata` 只返回每个增强器的最新规范观察与 provenance，不返回凭据。

## 4. 缺失、危险与解释

未知使用中性先验并降低 coverage/confidence；不适用从分母移除，不降低覆盖度。`integrity-v1` 独立读取每个官方增强器的最新观察，且只有实际存在 `is_retracted` 或 `updates` 字段才计入完整性覆盖度。OpenAlex 的 `is_retracted` 来自 Retraction Watch；Crossref 的 `update-to`/Crossmark 只用于编辑上显著的更新，支持撤稿、关注声明、更正、部分撤稿和恢复声明等类型。[OpenAlex Work 字段](https://developers.openalex.org/api-reference/works/get-a-single-work)、[Crossref Retraction Watch 数据](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/)、[Crossref 更新类型](https://www.crossref.org/documentation/crossmark/participating-in-crossmark/)

撤稿记录仍可查看，但 `eligible_by_default=false` 是排序前硬门槛，任何相关性、质量或偏好高分都不能抵消。关注声明/部分撤稿保留推荐资格但显示强警告，并把最终置信度上限压到 40；重大更正、勘误和恢复声明上限为 70。较新的恢复声明只有在日期可验证且 OpenAlex 不再标记撤稿时才解除默认排除；来源冲突继续默认排除并显示冲突警告。完整性规则不改写原始质量分，而是和原始分数一起冻结进 `ScoreSnapshot.hard_constraints`，因此既保留历史评价，也不会把危险论文静默排回结果。

每个 `ScoreSnapshot` 保存规则版本、权重、原始证据、字段来源、缺失策略、完整性硬约束和最终公式。

## 5. 推荐配额

每批默认 20 篇、候选最多 50 篇。`composite-v1` 先按默认资格与综合分形成最多 50 篇候选，再把目标批次向上取整的 20% 留作探索；默认 20 篇即 16 篇利用、4 篇探索。利用槽取综合分最高论文；探索槽只接受带确定性证据的 `adjacent_topic`、`new_author` 或 `source_diversity`，使用贪心覆盖先尽量包含不同原因，再按原因数、综合分和 Work ID 稳定选择。Agent 不能创建探索标签。

如果合格探索论文不足，空槽按综合顺序回填为利用项并记录 `exploration_candidates_unavailable` 或 `exploration_quota_partial`，不会为了凑比例越过撤稿/关键词硬门槛或 50 篇候选上限。历史已读、收藏或分析论文先从新候选池分离，按同一综合规则形成 `historical_matches`，既不占最多 50 篇候选，也不占默认 20 篇新论文配额。不喜欢与关键词/撤稿硬门槛一样在默认排序前抑制，但用户可明确查看并看到 `preference:disliked` 原因。

## 6. 偏好

显式信号：收藏、喜欢/不喜欢及原因、兴趣作者。隐式信号仅包括列表/详情/PDF 打开、阅读时长分桶、阅读完成和生成报告；不记录键盘、鼠标或系统浏览行为。原始隐式事件保留 180 天，之后仅保留不可逆聚合权重。

`preference-v1` 使用 50 分中性先验，把个性化与客观质量完全分离：喜欢增加 20，收藏增加 10，命中用户明确关注作者增加 10，受限行为总权重最多增加 10，最终封顶 100。行为权重固定为列表打开 0.25、详情打开 0.5、PDF 打开 1、阅读完成 4、生成报告 3；阅读时长仅保存 `<30s`、`30s–2m`、`2m–10m`、`≥10m` 四个分桶，对应 0.25/1/2/3，不保存连续时长。原始与已聚合权重共同计入同一 10 分上限，频繁打开不能无限抬高排序。

覆盖度只由实际存在的偏好证据贡献：明确喜欢/不喜欢 50、收藏 20、兴趣作者命中 15、受限行为 15；无信号时仍为中性 50 分，但覆盖度和置信度均为 0，不伪称了解用户。不喜欢不是低分证据，而是独立 `suppressed_by_default` 硬规则，偏好高分、相关性或质量均不能抵消。收藏、阅读进度大于零或已有正式分析报告会标记历史匹配；置顶只影响库内展示，不偷偷增加论文分数。

`/api/v1/library` 提供独立库状态、兴趣作者、白名单事件和偏好分读取。浏览器不能提交事件发生时间，服务端按当前时间记录；未知事件类型与额外字段直接拒绝，同一事件键重试返回原事实。所有变更继续受本地会话、回环 Origin 与 CSRF 保护。

关键词建议使用独立的 `preference-context-v1` 隐私缩减投影。服务端只从收藏、喜欢、关注作者所关联 Work 的规范标题/摘要，以及 180 天后已不可逆聚合的总权重中提取最多 12 个研究词；不读取反馈原因、原始隐式事件、笔记、报告、聊天、路径或私有 PDF 正文。`GET /api/v1/keywords/preference-context` 返回用户可见的词、相对权重、来源类别和内容 SHA-256。向导默认展示并启用这些词，用户可在调用 Agent 前关闭；建议命令只接受启用开关和可选 SHA-256，浏览器不能提交自造 `preference_terms`。上下文变化会返回 409 并要求重新审阅，不能静默发送旧内容。偏好上下文只进入建议 provenance，绝不直接进入检索；仍只有用户确认的不可变关键词版本可以筛选论文。

## 7. 证据优先的持久推荐编排

`recommendation.run` 是发现结果与正式推荐之间的持久边界。任务创建时冻结发现运行、候选 Work、确认关键词版本、评分时间、质量规则版本与权重、每个 Work 的最新元数据观察 ID、固定/滚动月份语义和配额。准备阶段一次性计算候选范围内的相关性、七维质量、完整性、偏好、新鲜度与探索原因，并把规范 JSON 写入 checkpoint；重启后只读取该检查点，不重新读取可能已经变化的偏好、模型状态或增强数据。

每个候选随后分别追加 relevance、quality、freshness、preference 和 composite 五个 `ScoreSnapshot`。单项快照以内容寻址保证重试幂等；全部候选成功后才创建不可变 `RecommendationSet`。任一构建或持久化错误只把 Job 标记为失败，既不创建半成品结果集，也不替换该运行上一版正式结果。用户重试时沿用已准备事实与已完成快照；固定历史月份把新鲜度显式记录为未参与，并在 composite 中使用 45% 相关性、45% 质量、0% 新鲜度、10% 偏好。

发现运行进入 `succeeded` 或 `partial_success` 后自动触发首轮推荐；元数据增强进入 `succeeded` 或 `partial_success` 后以增强 Job ID 触发独立评分轮次。两条链路都有稳定幂等键，取消或完全失败不会触发新正式结果。语义模型缺失或运行异常仍由相关性层诚实降级为词法与关键词证据，降低 coverage/confidence 而不阻断推荐；应用在准备任务的瞬间读取当前语义运行时，因此启用模型后无需重启。OpenAlex 归一化引用百分位/FWCI 是引用表现主证据，Semantic Scholar 原始引用只保留为交叉核验；作者或机构名称、缺失字段以及未被论文明确关联的代码/模型热度永不被推断为质量证据。

Agent 无权写入 ScoreSnapshot、排序权重、LibraryState 或反馈。任何个性化变化都必须由确定性规则和可审计事件产生。

## 8. 结果读取与阅读简报

`GET /api/v1/runs/{run_id}/recommendations` 只读取该运行最新的正式 `RecommendationSet`，支持 `composite`、`relevance`、`quality`、`newest`、`preference` 五种视图。每篇论文分别返回相关性、质量、新鲜度、偏好和综合分的 score、coverage、confidence、规则版本与快照 ID；列表只保留完整性状态、排除原因、探索原因和警告代码等紧凑摘要，不传输逐维原始证据。完整组件、权重、缺失策略、观察 ID 与硬约束通过 `GET /api/v1/scores/snapshots/{snapshot_id}` 单独读取，浏览器不重新计算评分。

结果项同时保留当时评分使用的 `scored_work_id`，并把标题、作者、来源与论文库状态解析到当前规范 `work_id`。因此人工合并不会改写历史评分证据，也不会让界面继续展示已合并的旧身份。历史匹配位于独立集合，不占新论文配额；默认列表不返回被完整性、关键词或不喜欢硬约束排除的候选，用户显式开启后仍可看到其原因。

`POST /api/v1/runs/{run_id}/recommendations/refresh` 创建幂等的 `recommendation.run` Job，只接受空命令和可选幂等键；模型、后端、提示词等 Agent 参数由关闭式 schema 拒绝。刷新沿用同一确定性评分边界，后台失败不会替换上一正式结果。

`GET /api/v1/briefing` 是首页“阅读简报”的本地事实投影：关注计划及其最新运行、新论文、未读重要修订、待确认补跑、进行中和失败任务。它不调用 Agent、不读取任务私有 payload，也不把论文正文或完整评分证据装入首页响应。首次使用和已有计划但暂无动态时返回显式空状态及对应下一步。

## 9. 用户反馈闭环与离线降级验收

推荐界面的显式反馈先写入独立 `LibraryState`，服务端返回保存事实后才刷新卡片；浏览器不乐观伪造偏好分。下一次不可变推荐集可以读取更新后的偏好快照，因此“最符合偏好”视图可能改变顺序，但旧推荐集及其五类快照保持不变。下一次关键词建议读取新的 `preference-context-v1` 哈希和用户可见研究词，仍须再次人工确认，不能把反馈直接变成检索条件。

端到端验收固定覆盖以下因果链：先喜欢一篇论文 → 新计划展示该显式偏好的聚合词 → 用户用键盘关闭并重新启用 → Agent 返回 18 个中英双语词 → 用户手工修改并确认新版本 → 两个来源预览 → 一个来源限流形成部分成功 → 五种排序共享冻结事实 → 新反馈改变下一轮偏好排序和建议上下文 → 首页把重要修订放在“不占新论文配额”区域。进入结果、切换视图、保存反馈和查看简报期间，分析 endpoint 调用数必须为零；点击“分析”后才读取报告与预检，仍不会自动创建正式报告 Job。

无 API key、无偏好历史、无模型的验收使用同一主流程，而不是专用演示页：只启用免费来源，本地语料/受控词表生成约 18 个双语词，确认后完成月份预览、运行和推荐。语义与质量增强不可用时，界面必须同时展示退化原因、综合覆盖度和置信度；七项质量证据全部未知时，冻结质量分仍是中性 50、coverage/confidence 为 0，列表显示“未知”而不是 0 分。

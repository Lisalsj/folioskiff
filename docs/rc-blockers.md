## 处理规则

1. 不再触发、重试或为了“看一眼”推送 GitHub Actions；额度恢复前所有收据来自本机并明确标注。
2. 安全问题先保留最小失败测试，再做最小修复；精确测试和领域测试通过后才运行全量门禁。
3. 每次重建都会使旧 artifact 收据失效；版本、提交、文件大小和哈希必须整体替换，不能混用。
4. 外部限制只能透明披露，不能伪造 key、管理员权限、干净机、屏幕阅读器或签名收据。
5. 凭据、用户名、绝对本机路径、论文内容和用户资料不进入本文或发行收据。
6. 额度恢复后必须串行执行：只推送 `main` → 等待并核验 CI → 只推送 `v1.0.0` → 等待并核验 Windows 打包链 → 核对 draft 资产 → 确认公开可见性后发布；禁止一次命令同时推送分支和标签。

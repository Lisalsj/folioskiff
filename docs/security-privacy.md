## 1. 威胁模型

需要防护同机恶意网页访问本地服务、URL 密钥泄漏、CSRF、路径穿越、日志/备份泄密、插件越权、恶意 PDF、论文提示注入和供应链污染。不承诺抵御已完全控制用户账户或操作系统的攻击者。

## 2. 本地 HTTP 会话

- 服务只绑定 `127.0.0.1`，端口动态选择。
- 用户状态根的 `instance.lock` 使用不可继承的 Windows byte-range lock；只有内核锁是所有权事实。`instance.json`、陈旧 PID 或可连接端口都不能取得所有权。
- 锁文件、原子临时文件、`instance.json` 和显式 smoke ready 文件使用当前用户 SID 的 protected DACL，不继承 Everyone、Users 或 Authenticated Users ACE；链接、junction/reparse point 和打开期间身份变化全部拒绝。
- 首进程完成恢复、迁移和 Uvicorn startup 后才发布激活状态并打开浏览器。第二进程只执行直连回环激活，不创建 App、数据库、迁移、Job 或监听 socket；无法验证现有实例时稳定失败，不启动竞争实例。
- 启动器生成高熵一次性 bootstrap secret，放入 URL fragment，不进入 HTTP 请求日志。激活 secret 只存在于受保护状态文件和进程内存，不进入 URL、ready 文件、错误或结果。
- SPA 读取后立即清除 fragment，再交换 HttpOnly、SameSite=Strict 会话 cookie。
- 初始和激活签发的 bootstrap token 默认 5 分钟过期、容量有界，成功使用一次后立即失效；bootstrap 只接受无用户信息、路径、查询或 fragment 的纯 `http` 回环 Origin。
- `/api/v1/session/activate` 同时要求实际对端是回环地址、Origin 缺失或为严格回环 Origin、constant-time secret 比较、1 KiB 流式请求上限和关闭式 JSON；返回 PID 必须与状态文件一致。
- 所有变更请求同时验证有效会话、回环 Origin、非 HttpOnly CSRF cookie 与 `X-CSRF-Token`。
- 会话默认 12 小时过期，服务端与 cookie `Max-Age` 使用同一截止时间；默认最多保留 64 个、配置上限 256 个会话，过期项与最旧项会被淘汰且不能重放。退出时全部失效。任何 `/api` 未知路由返回 JSON 404，不回退 SPA。

## 3. 凭据

Codex 只复用 CLI 登录状态，不读取、复制或改写 Codex 配置。Ollama Cloud 和来源 API key 使用 Windows Credential Manager；配置文件只保存凭据引用。日志、诊断包、备份、精选发布、异常消息和插件 payload 默认不含 key、cookie、bootstrap secret 或完整 Authorization 头。

开发与只读 live smoke 可通过进程环境变量临时注入来源/增强器 key；应用只在启动时读取，能力 API 仅暴露 `configured` 布尔值，不会回显值。普通配置由本地受保护变更接口直接写入 Windows Credential Manager，保险库值覆盖环境回退；密钥既不进入 SQLite/WAL，也不进入 Job、OpenAPI 响应或生成内容。

元数据增强凭据分为 OpenAlex API key、可选 Semantic Scholar API key、Crossref 联系邮箱和可选 Metadata Plus token。每项使用独立保险库名称与独立保存/删除接口；联系邮箱虽然不是密钥，仍按个人信息放入保险库。设置页只取得标签、是否必需、是否敏感和配置状态；输入提交成功后立即清空。Crossref 邮箱在写入前做基本格式校验，任何错误响应都不包含原值。

首次配置向导遵守同一凭据边界。来源接口只返回能力和 `credential_configured` 布尔值，密钥输入不会进入 Pinia 状态；提交结束后无论成功或失败都清空 DOM 值。Agent 探测只返回闭集诊断码、受限长度的可打印版本和模型标识，不读取或复制 Codex 登录凭据，也不以生成请求测试能力。

## 4. 文件与网络

运行路径配置位于固定状态根下的关闭式、版本化 `runtime-config.json`，不进入数据库且不允许包含凭据。变更接口要求本地会话、Origin 与 CSRF，通过临时文件、同步和原子替换发布；缓存与论文库必须是规范化绝对路径，论文库不得位于状态根内。状态根不能由首次配置向导迁移。路径保存完成后只有在解析值确实变化时才返回 `restart_required=true`，重启需要独立受保护请求，避免普通表单保存隐式终止服务。

所有用户路径先规范化并验证仍位于授权根目录。下载使用大小/类型上限、临时文件、SHA-256 和原子落盘；PDF 解析只接收内容哈希对应的精确库内路径，并在不阻塞 HTTP 的受监督短命 worker 中执行。插件默认无网络、文件和凭据权限，按能力显式授权。模型/OCR 下载校验版本、许可证和哈希。

官方来源返回的 XML 属于不可信网络输入。arXiv Atom 响应使用禁止 DTD、外部实体和实体扩展的 `defusedxml` 解析器；普通语法错误和防御性解析拒绝都映射为同一个稳定、不含响应正文的 `response_incompatible`。SQLite 查询不把外部 ID、关键词或向量记录 ID 拼入 SQL；可变集合通过绑定参数或 `json_each(?)` 传入，避免动态占位符字符串形成新的注入面。

手工 PDF 上传必须先确认合法取得，使用 FastAPI 的本地临时文件按 64 KiB 分块送入 100 MiB 上限的内容存储；文件名只保留安全 basename，最终字节还必须以 PDF 魔数开头。内容先在库根目录同一文件系统写入随机 `.part`、同步并原子替换，API 只返回文档 ID 和哈希，永不返回相对或绝对本地路径。

阅读器只通过受本地会话保护的 `GET /api/v1/documents/{document_version_id}/content` 取得 PDF。接口先解析文档行与规范 Work，要求 Work 已在本地论文库、权限为 `open/user_provided`、媒体类型为 PDF、相对路径精确等于内容哈希分片规则，并拒绝路径穿越、符号链接、junction、缺失文件和字节数变化；不存在或不属于论文库返回 404，元数据存在但字节已不可合法读取返回不含路径的 410。成功响应固定 `application/pdf`、`inline`、`nosniff`、`private, no-store`，使用框架 byte range 支持 PDF.js 分段读取，并只在全部校验成功后刷新 `last_accessed_at`。浏览器永远看不到库根目录或持久化相对路径。

阅读位置与批注接口同样要求本地会话和论文库归属，所有写操作同时校验 Origin 与 CSRF。客户端必须回传当前文档内容 SHA-256；与数据库中不可变版本不一致时返回 409，不能把旧页面选择静默写到新文件。页码、页面尺寸与所有坐标必须有限、为正且位于未旋转 PDF point 页面边界内；引用、上下文和笔记均有长度上限。API 只返回文档 ID、内容哈希、引用证据和规范坐标，不返回任何本地路径。更新或删除批注只改变批注记录，不能修改页级原生/OCR 证据。

引用 URL 只允许无内嵌凭据的 HTTP/HTTPS，规范 IDNA 主机、默认端口并移除 fragment，同时拒绝 localhost、`.local`、私网/回环/链路本地字面 IP。引用导入本身不发请求；只有用户因打开、保存或分析论文而明确触发 `reader.acquire_document` Job 时，才允许下载已声明为 `open` 的直接 PDF。

开放 PDF 下载器使用不读取系统代理环境的独立客户端，在初始 URL 和每次重定向前都重新解析 DNS，要求所有结果均为公网地址，并在连接后复核实际对端仍属于刚验证的地址集合；无法取得对端地址时按失败关闭，以阻断私网重定向和 DNS 重绑定。客户端关闭自动重定向与内容压缩，只接受 PDF/通用二进制 MIME；既预检 `Content-Length`，又对实际流量执行 100 MiB 硬上限，最后仍验证非空 PDF 魔数。响应按流写入库根目录同一文件系统的随机 `.part`，只有哈希、同步和最终取消检查全部通过后才原子提交；超时、截断、错误类型、超限、取消或任意跳转失败都会关闭响应并删除临时文件。

下载 Job 的 payload 只保存规范 URL、Work/来源记录 ID、开放权限声明和触发原因，不保存凭据或本地路径。进度/checkpoint 先持久化再发布 SSE 事件；启动时只恢复 `queued/running` Job。幂等键复用原命令，同一 Work 与内容哈希最多形成一个 `DocumentVersion`；取消以终态事件结束且不提交文档行。用户可见错误使用 `unsafe_url`、`dns_failure`、`too_large`、`not_pdf`、`truncated`、`redirect`、`network`、`cancelled` 或脱敏内部错误分类，不回显底层连接异常。

原生文本提取每份 PDF 最多 2,000 页；打开后若需要密码、结构不可解析、曾由 MuPDF 修复、页数越界或运行时不可用，会分别形成 `encrypted`、`damaged`、`too_many_pages` 或 `extractor_unavailable`，不回显底层解析器诊断。文本只做保守 NFC 与换行规范化，不执行脚本、不解析外部链接，也不调用 OCR。扫描页必须同时满足原生非空白字符不足 32 且显示图像覆盖至少半页；纯空白页不会触发后续 OCR。每页坐标被裁剪到有限的页面边界，整份结果验证后才原子替换数据库页记录。

不可信 PDF 还受独立资源预算约束：单页任一边不超过 14,400 point、面积不超过 25,000,000 square point、文本块不超过 20,000、图像对象不超过 10,000、解码文本不超过 2,000,000 字符；整份文本块不超过 200,000、解码文本不超过 20,000,000 字符，单次原生提取完整生命周期时限为 120 秒。页数/几何在文本解码前检查，文本集合返回后立即检查数量；只有原生文字不足扫描阈值时才枚举图像，避免正常文本页扩大图像解析面，并在每 128 个对象边界复核取消和时限。超限使用 `page_too_large`、`too_many_blocks`、`too_many_images`、`too_much_text` 或 `time_limit`，消息不含文件路径、正文或原生异常；任何一页超限都不会发布本批部分页证据。

应用关闭造成的协程取消会向原生 worker 发出停止并在 Windows Job Object 边界终止残留进程，Job 与 checkpoint 仍保持可恢复状态；只有用户通过取消 API 明确请求时才写入 `cancelled` 终态。解析失败和取消都保留上一次完整页证据，不会把部分文本暴露为当前结果。页证据读取时再次校验文档当前仍为合法可访问的 PDF；权限后来变为受限时，即使保留旧审计行也不会通过 API 返回正文。

E5 与 OCR 都是显式安装、显式启用的可选能力。两类内置关闭式清单固定 revision、HTTPS 443 主机、资产路径、大小、SHA-256、许可证和用途；API 在下载前只展示必要的公开来源与许可事实，不返回资产 URL、查询参数、响应正文或本机路径。下载不读取环境代理，每次重定向都重新校验 scheme/host/端口、DNS 公网解析和实际 peer；响应头、正文、声明长度、磁盘余量及最终字节均有硬上限。Windows 相对路径还拒绝 ADS、保留设备名、尾随空格/点和任何链接或 reparse point 边界。

临时 `.part` 与 `.part.json` 只能位于目标 revision 目录；检查点绑定强 ETag、已验证长度和部分 SHA-256。断网、应用关闭或用户暂停可以保留可复验部分，服务器忽略 Range、Content-Range 不匹配、ETag 变化或部分字节被篡改时从零开始；用户取消、无效清单或不可信响应会清除未完成字节。完整资产必须先同步、校验精确长度与 SHA-256，再原子发布。只有全部资产和运行时激活检查通过的 revision 才能成为活动版本；当前活动、运行中或仍被 OCR Job/语义索引引用的版本不能删除。

能力探测先检查可选模块是否存在，再在隐藏的短命子进程中执行一次 RapidOCR/ONNX Runtime 导入健康检查；超时、进程启动失败、原生 DLL 初始化失败或非零退出都统一显示 `runtime_unavailable`，诊断输出不回显到 API。主服务进程不会因此加载可选原生库。RapidOCR 只在用户点击扫描页 OCR 后于受监督 worker 中惰性加载，并且只接收本地 PDF 页渲染出的 PNG 字节；按 2 倍比例渲染前后都执行 25,000,000 像素硬上限，超大页面不会进入 PNG 编码或模型。OCR 前后都重新校验论文仍在本地库、权限为 `open/user_provided`、媒体类型/哈希/路径安全、原生提取已完整且页证据未变化。识别行的文本、有限坐标和 0–1 置信度全部验证并裁剪到 PDF point；任何页面失败、用户取消、回调异常、文档并发变化或引擎版本异常都丢弃本批临时结果。OCR 不访问网络、不处理普通文本页，也不修改原生证据。

一次 OCR 最多处理 500 个扫描页；每页仍受 25,000,000 渲染像素、64 MiB PNG、10,000 识别行和 1,000,000 输入字符限制，整份识别行不超过 200,000、OCR 输入不超过 10,000,000 字符，完整生命周期时限为 1,800 秒。页面渲染、PNG 编码与模型调用前后都检查取消和时限；`too_many_pages`、`page_too_large`、`image_too_large`、`too_many_lines`、`too_much_text` 与 `time_limit` 均为关闭式、脱敏错误。所有页面和引擎版本通过后才在一个事务中写入 OCR 证据，因此超限、取消和模型失败不会留下正式部分结果。

PDF.js 使用独立 worker，并固定 `isEvalSupported=false`、`enableXfa=false`、`stopAtErrors=true`、25,000,000 图像/画布像素上限。浏览器最多接受 2,000 页；显示页面任一边最多 14,400 CSS pixel、面积最多 100,000,000，文本层每页最多 20,000 项/2,000,000 字符，全文搜索累计最多 20,000,000 字符。搜索完一页即释放非活动页文本缓存，超限时取消当前画布任务并显示可恢复的中文说明，不展示 URL、路径或 PDF 正文。

PyMuPDF 与 RapidOCR 的生产路径已移入短命 worker。监督器用一个 deadline 覆盖进程启动、请求写入、状态、结果收据和退出；超时或取消先终止 worker，再关闭 Windows Job handle 杀死残留成员。Job 同时限制活动进程数和进程/作业内存，父进程重新验证关闭式结果协议、整份块/行总量、字节数与 SHA-256。worker 使用重建的可信 `PATH` 且不继承 API key、token、cookie 或用户 `PYTHONPATH`。这提供硬终止、资源与协议隔离，但不是 AppContainer：未知原生零日若取得同用户代码执行，仍可能拥有该 Windows 用户本来可访问的文件权限。完整发现与证据见 [v1 安全边界审计](security-audit-v1.md)。

模型设置首屏只执行清单与持久任务的只读查询，不创建 Job、下载或启用文件。模型专用任务响应是关闭式最小投影，只包含资产 ID、稳定状态/错误码、服务端进度、是否可重试和公开时间，不包含完整 payload/checkpoint/result、`error_message`、异常、响应正文或本机路径；前端只把关闭式错误码映射为稳定中文说明。许可和来源链接在渲染前必须是无内嵌凭据的 HTTPS 443 URL，并移除 query 与 fragment。下载确认和旧版删除确认使用独立可访问对话框；删除按钮只有在最新服务端预览仍允许时出现，阻塞引用只显示归类数量而不显示内部任务或索引 ID。

JCR、CAS 与新锐榜单只接受用户在本机明确导入，不从网络抓取、不上传、不发布。导入前必须确认合法使用权；CSV/XLSX 最大 10 MiB、20,000 行，XLSX/CSV 公式、重复归一名称/别名、无映射等级和越界分数会被拒绝。系统只在 SQLite 中保存评分所需的规范行与原文件 SHA-256，不保存或对外提供原始文件；三类商业或本地榜单在数据表、活动指针和评分证据中始终分离。

外部产物热度只能由明确的论文—产物证据解锁。自动关系提取只接受 Crossref 中由论文主体声明的受控关系和规范 HTTPS GitHub/Hugging Face 资源；相似名称、任意网页、Issue/PR 地址和 Agent 生成内容不构成证据。产物指标必须与规范资源身份精确相同，未关联的高热度指标会被记录为忽略项，不能进入质量分。

### 备份与恢复边界

便携备份只从 SQLite online backup 快照和数据库当前引用的合法内容寻址 PDF 构造。完整 SQLite 状态意味着包内会包含研究计划、元数据、评分证据、提取文本和 OCR 全文、阅读进度、批注、正式报告、完整提示词、脱敏失败诊断、论文聊天、偏好以及已冻结发布快照；创建与恢复界面必须在确认前明确显示这些私密类别。凭据、模型、向量与派生缓存、日志、临时文件、旧备份和未被数据库引用的对象没有进入归档的代码路径。未加密包可被取得文件的人直接读取，界面必须持续警告；可选密码采用流式 AES-256-GCM，密码只存在于一次消费并清零的进程内租约。明文临时包、密文失败产物、上传和解密 staging 在取消、失败、关闭或下一次启动时安全清理。

备份 staging 与最终归档位于同一备份目录以保留原子发布语义，但 staging 只使用固定短前缀和随机 UUID，不重复可能很长的用户可见归档名；随机名以排他创建打开，碰撞不会覆盖既有文件。该规则为未启用 Windows 长路径支持的个人目录保留额外路径余量，失败或取消仍删除临时字节。

恢复采用两个明确授权点：上传只触发隔离验证，用户看完不含路径的内容范围并确认当前 fingerprint 后才写入 `pending-restore.json`；当前进程不执行替换。下次启动在数据库引擎、迁移、HTTP 监听和浏览器打开之前，重新验证 pending、journal、stage、数据库和对象树的规范绝对身份、专用根归属、同卷、链接/junction、大小与 SHA-256。双根 journal 以可恢复 rename 发布数据库（含 WAL/SHM）和对象树，完整性检查与迁移通过后才提交；任何故障都回滚到完整旧状态或保留可继续的 journal，不允许混合数据进入应用。journal 临时文件先同步再原子替换；仅当 Windows 返回安全扫描器/共享竞争常见的 `winerror` 5 或 32 时，替换会在一秒内有界重试，超过上限或其他错误仍立即进入脱敏的安全回滚语义。

上传路径、staging/rollback 路径、密码和异常文本不进入 Job、SSE、恢复收据、日志或 API。恢复后的旧 `queued/running` Job 统一变为 `restored_interrupted`，防止重放网络下载、Agent、OCR、插件或发布副作用。恢复包永远不覆盖当前机器的凭据、模型和 cache。

## 5. 插件与 Agent 隔离

### 插件

插件主进程发现阶段绝不执行 entry point `.load()`；重复 ID、非法模块属性、缺失或
异常 distribution metadata 均保持隔离。manifest 只接受五类固定能力与方法，配置
schema 禁止远程引用和未知关键字；网络只声明 DNS 域名，文件/凭据只声明抽象 broker
resource。安装记录默认禁用，entry point、版本或 manifest hash 变化会使当前授权失效。
权限审计只追加 grant/revoke 并绑定确切版本/hash，数据库没有 secret/value 字段。

发现刷新必须由用户在设置页显式触发。主进程只枚举可信 distribution metadata；完整
manifest 通过无 broker、无业务权限的 `plugin.manifest/probe` 在 AppContainer 内读取。
该探测禁止事件、broker 请求和额外结果字段，并复核插件 ID、distribution 名称与版本；
任一插件失败只返回稳定问题码，不泄漏 stderr、路径或异常文本，也不阻止其余插件登记。
本次刷新未发现或未验证的旧安装会 fail closed：立即停用、只追加 revoke 当前 grant、
清除熔断并移出运行 registry；旧清单和权限历史只作审计，不能继续调用残留代码。

JSONL 在解析前验证单一 LF、严格 UTF-8、控制字符和字节上限；每帧必须关联同一 UUID
请求、协议版本和连续 sequence，唯一终态后拒绝额外输出。宿主先验证启用状态、协议、
capability、方法、当前版本授权、deadline 和请求大小，再创建调用目录；任一步失败都执行
零次插件调用，也不能增加插件失败计数。

Windows 插件进程使用无 capability SID 的一次性 AppContainer，并在首条指令前加入
单进程、内存受限、kill-on-close 的 Job Object。worker 复制进 profile 后执行，工作目录、
临时目录和 PATH 都在 profile 内，只继承三条标准流；数据库、凭据环境、宿主可执行目录和
任意用户文件均不挂载。原生能力探测、profile、Job、句柄限制或进程建立失败时统一关闭为
`sandbox_unavailable`，没有普通 subprocess 后备路径。真实恶意 fixture 已验证宿主文件
读写、凭据环境、loopback/公网 TCP、子进程和宿主 DLL 加载均被系统边界阻断，乱码、无限
输出和无限内存会终止整个 Job，之后宿主仍可执行正常调用。

唯一出站通道是 host broker：网络只到当前能力获批的精确 HTTPS 域，每跳重验 DNS 与
实际公网 peer，禁用环境代理、私网、凭据 URL、任意端口和无限响应；文件只按抽象 ID 分块；
凭据只按获批别名返回，并对后续事件、结果和异常执行本次调用内的精确值脱敏。连续三次
超时、崩溃或协议失败只熔断该插件，计数以原子 SQL 更新；broker request ID 不可重放，
单次调用最多 128 个唯一 broker 请求，防止用小帧绕过副作用预算。其他插件不受影响，恢复
必须由用户显式 reset。

领域适配层只持有 host 调用面，不注入数据库或 repository。只有 enabled、协议兼容、
当前清单权限全部批准且 sandbox 健康的 capability 才会进入 registry；停用、撤权或熔断
立即原子移除。插件结果经过关闭式、限长 schema 验证后才形成领域对象，内置 ID 冲突
永不覆盖内置能力，插件也没有修改评分、排序、反馈或已有正式报告的接口。
来源、增强器或 Ollama Cloud 凭据变化时，宿主在原 registry 对象内替换内置实例，再
重新注入获批插件；长寿命的计划、评分和分析服务因此不会与设置页持有不同能力集合。

插件开发者只能使用 [`PluginApplication`/`PluginContext` 的受限 SDK](plugin-sdk.md)。v0.6 不提供市场、自动安装、普通进程调试后备或通过 fixture 冒充 live capability 的路径；离线示例只验证协议。插件若确需网络、文件或凭据，必须在 manifest 中声明精确资源，并由用户在设置页逐项批准后通过 broker 使用。

### Agent

Codex 工作目录按任务创建，只读放入应用明确构造的证据附件；sandbox、MCP 禁用清单、工具能力和网络参数由应用代码显式传入，论文内容不能影响进程参数。论文正文、元数据、标注、历史消息、用户问题、比较中间结果和模型输出永远属于不可信数据，在提示词中使用确定性 JSON 与编码后的结构分隔符，不能覆盖安全契约、调用 shell/MCP/插件、读取凭据、修改评分或扩大网络/文件范围。外部研究只有显式开关可以启用；正式报告中的外部陈述必须使用独立 `external:*` 引用和无凭据 HTTPS URL，引用清单存于报告记录而不混入论文证据包。

相关推荐的本地草案不经过 Agent。显式精炼在调用后端前重新验证不可变上下文、证据 JSON 哈希、每页文本哈希、文档内容哈希和 Work 身份；任一漂移保持零模型调用。`RELATED_INTENT` 固定禁止外部研究，丢弃流式内容，只接受封闭 schema 的 6–20 词结构，并拒绝模型增加当前草案之外的来源 ID。持久历史只保存最小模型身份以及提示词/原始响应 SHA-256，不保存原始响应、凭据或路径；差异在读取时从相邻修订重新计算，伪造历史会失败关闭。

相关推荐的学术阶段只信任已确认的当前意图修订，并把连接器响应视为不可信输入。来源 ID 必须与注册连接器一致，外部 ID、标题、作者、日期与 DOI 均有长度、控制字符、时区和格式边界；每来源最多 3 页、全局最多 50 条，单次身份入库也限制为 50 条。可点击论文地址只允许无凭据、非 IP、默认端口的 HTTPS 域名，`javascript:`、`file:`、本机名和来源身份伪造均在写 Work 前关闭失败。Agent 文本不参与 DOI、来源 ID、Work 或 merge review 判定。

外部知识资源必须同时具有当前确认修订、持久化联网同意和支持外部研究的 Agent 能力。`RELATED_EXTERNAL` 的模型输出只是不可信提案；URL 最长 2,048 字符，只允许证书校验的 HTTPS 443、多标签公开 DNS 名称，拒绝 IP 字面量、用户凭据、常见令牌/签名查询参数、本机/`.local`/`.localhost`、非公共或混合 DNS 答案。探测连接直接固定到已验证 IP 并保留原域名 SNI，在写出 HTTP 请求前核对 peer；每次重定向重新执行相同策略，最多 5 跳。默认只用 HEAD，必要的 Range GET 最多 64 KiB，使用单一总超时且不继承系统代理。短链、搜索结果、已知复制/下载服务及归档/可执行文件不会进入已验证资源；拒绝诊断剥离用户信息、查询和片段，只保留域名与不可逆短摘要。

视觉输入同样遵循最小证据原则。只有冻结文本明确指向关键图、表或公式，且已探测模型明确支持视觉、用户策略允许时，才在执行前重新校验同一 PDF 内容哈希并在内存中渲染最多 6 个受限 PNG。文件名绑定文档哈希与页码，不生成持久页图；Codex 仅使用 `--image` 参数，Ollama 仅把 Base64 放在相关首条消息。能力未知、文本充分、策略关闭、哈希变化、超限或取消均不会扩大为任意 PDF/文件访问。

分析预检不创建任务、不调用模型；正式分析命令必须同时通过本地会话、回环 Origin、CSRF、幂等键和当前预检指纹校验。持久 Job 不含凭据或本地路径，并在调用后端前重新计算冻结证据、完整提示词和请求指纹，同时复核安装、认证与后端能力；完整性异常只保存脱敏诊断，不把被篡改内容发送给模型。只有用户曾明确创建的 queued/running 分析任务才允许在重启后恢复。报告、片段、失败草稿与导出响应全部禁止缓存；自包含 HTML 通过 CSP 禁止加载外部资源、提交表单或被其他页面嵌入。

## 6. 隐私与保留

单用户、零遥测。只记录应用内有限事件，不记录键鼠或系统浏览。凭据不进入备份；SQLite 中的私有研究记录会进入便携包，是否离开设备完全由用户下载和保管行为决定。诊断包只手动导出并先展示脱敏清单。精选发布默认拒绝 PDF、私有笔记、聊天、行为、偏好、凭据和完整提示词，只有白名单字段可以进入快照。逐类事实与通道见 [v1 隐私与无障碍审计](privacy-accessibility-audit-v1.md)。

时区与主题保存在本地 SQLite 并随便携数据库备份；它们不属于精选发布内容。浏览器本地缓存只允许关闭式 `system/light/dark` 主题值，用于服务端响应前避免闪烁，不保存时区、论文、路径、会话、行为或凭据。偏好接口与其他本地变更一样受一次性启动会话、回环 Origin 和 CSRF 保护。

精选预览的服务端查询采用逐列白名单，不读取报告的完整提示词/证据清单，也不读取评分快照的组件、权重、缺失策略或硬约束。公开论文事实只来自解析合并关系后的最新活动 Work；报告正文必须来自用户明确选中的正式不可变版本，并把本地 `evidence_id` 收缩成公开页码/图表定位或独立 HTTPS 外部引用。失败草稿、未选报告、来源原始响应、DocumentVersion 路径/全文、批注、聊天、偏好事件、插件配置和进程环境没有进入发布模型的字段入口；客观质量证据缺失时输出 `null`，客户端和 Agent 都不能补造。

预览完全只读，其指纹同时绑定公开载荷、原始选择、规范 Work 更新时间、最新正式报告修订和最新客观质量快照。确认时服务端在同一个 SQLite `BEGIN IMMEDIATE` 事务内重新计算指纹、渲染并写入快照，竞争更新不能插入复核与冻结之间；任一既有依赖变化都会拒绝旧预览。确认后 `PublishedSnapshot` 冻结选择和公开 payload，按用户顺序绑定 Work/明确报告/客观质量快照，并保存 `index.html`、`data.json`、`manifest.json` 的原始字节、大小与 SHA-256；快照哈希还覆盖选择、预览指纹和完整文件清单。三张表的更新和删除均由数据库触发器拒绝。

发布 HTML 只使用确定性服务端渲染：所有题名、导语、作者、摘要和报告陈述先做 HTML 转义；内嵌 JSON 额外转义 `<`、`>`、`&` 和 Unicode 行分隔符，不能闭合数据脚本。页面没有外链脚本、表单或 `base`，CSP 默认拒绝全部资源并显式禁止脚本、表单提交和嵌入。独立 JSON 与 manifest 使用规范键排序和 UTF-8 字节，同一快照必然产生相同文件。

Git 发布必须先通过只读诊断和用户对当前目标指纹的显式确认。生产目标固定为当前仓库根、无凭据的 `https://github.com/Lisalsj/folioskiff.git`、`origin` 与 `published`；原始和 Git 解析后的 fetch/push URL 必须一致。本地 URL rewrite、credential/include/filter、HTTP header/cookie、remote helper，以及符号链接或 junction 形式的 `.git` 控制目录都会禁用发布。Git 子进程不使用 shell，清除可改变仓库、配置、SSH、diff、trace 和 askpass 行为的环境变量，不读取用户全局配置；系统凭据管理器可以为固定 HTTPS URL 完成非交互认证，但凭据不会进入 URL、Job、日志或快照。

发布只在内容寻址缓存根下建立 Git 已登记的 detached、`--no-checkout` 临时 worktree。站点文件通过 plumbing 命令按四项固定清单写入，不执行来源分支内容、clean filter、hook、签名或构建脚本；文件必须是普通单链接文件。首次发布建立与源码历史无关的空根，后续只接续远端 `published` 最新提交；push 固定为非强制的 `HEAD:refs/heads/published`，并发 non-fast-forward 形成可重试失败，绝不 reset、merge 或 checkout 用户工作树。成功、失败和取消都在验证缓存包含关系与 Git porcelain 注册路径后移除临时 worktree；陈旧记录只做 `prune --dry-run` 诊断。操作前后主工作树 HEAD、分支和包含未跟踪文件的 porcelain 必须逐字节一致。

随快照发布的 Pages workflow 只响应 `published` push，权限限定为 `contents: read`、`pages: write` 和 `id-token: write`，仅使用官方 checkout/configure/upload/deploy actions 上传 `site`；发布过程不运行 npm、Python 或用户内容中的代码。持久 Job 只保存快照 ID/哈希、预览与目标指纹和重试来源；公开结果只包含固定 remote/branch、commit、站点根和 workflow 路径，不返回凭据或绝对临时 worktree 路径。

偏好事件 API 使用枚举白名单且不接受客户端时间：仅记录列表/详情/PDF 打开、四档阅读时长、阅读完成和生成报告，不存在任意事件名、连续鼠标轨迹、键盘内容或系统浏览历史入口。事件键用于幂等而非跨设备跟踪。原始事件严格保留 180 天；应用启动时把过期行按 Work 求和后删除，只留下无法还原事件类型和时间的总权重。论文身份合并只能重绑定 Work ID，SQLite 触发器阻止篡改事件其余内容。

关键词偏好上下文是关闭式、可见的聚合视图：只允许收藏、喜欢、关注作者和已不可逆聚合行为四类来源，最多 12 个研究词。查询层不读取反馈原因或原始事件表；响应不包含 Work ID、论文标题、作者名、笔记、报告、聊天、文件路径或正文。上下文规范 JSON 计算 SHA-256，建议请求只携带用户看到的版本哈希和启用开关；服务端重新计算并在不一致时拒绝。`preference_terms`、`corpus_terms` 及额外字段不能由浏览器注入，云端或本地 Agent 收到的偏好内容与界面展示逐项一致。

全文缓存清理采用“预览后显式应用”，不会在后台静默删除。预览按内容哈希聚合同一物理 PDF 的全部 DocumentVersion 和 Work：只有所有关联 Work 均明确为“不喜欢”、最后访问严格早于保留边界，且不存在收藏、置顶、正式分析或任意标注时才可清理；中立/喜欢、恰在 90 天边界或状态未知均受保护。批注保护直接读取正式的 `document_content_sha256` 字段，不依赖旧占位列名；Work 合并删除相同哈希的重复版本前先迁移批注并保留较新的阅读位置。路径冲突、不符合内容哈希分片规则、符号链接、Windows junction 或越出论文库根目录的路径只会显示为受保护，不会进入删除集合。

预览令牌覆盖保留天数、内容哈希、关联 Work、最后访问时间、数据库路径和全部保护原因。应用前会重新计算同一时刻的快照；任一偏好、标注或文档状态变化都会拒绝旧令牌并要求重新预览。同一进程内同一令牌串行且幂等执行，执行前先验证全部候选路径，再逐个删除；物理文件已不存在按幂等成功处理。清理只清空共享哈希对应 DocumentVersion 的 `relative_path`，保留 Work、来源记录、内容哈希、字节数、反馈、提取审计状态和报告。

用户界面不展示后端返回的任意文件错误详情。超限、非 PDF、缺失本地文件、OCR 运行时失败和清理令牌冲突都映射为固定的可恢复文案；服务端诊断即使包含绝对路径也不能进入 DOM、通知或任务名称。导入对话框在客户端提供快速大小/类型反馈，但这不是安全边界，服务端仍独立执行合法取得、流量、魔数、路径和内容哈希校验。

## 7. 安全测试清单

回环绑定、bootstrap 重放、非回环 Origin、缺失/错误 CSRF、会话过期、阅读内容 404/410/byte range/安全头/访问时间、阅读位置/批注的库归属与哈希冲突、越界/非有限批注坐标、Work 合并与缓存清理中的批注保留、路径穿越、符号链接/junction 逃逸、缓存清理预览过期与并发幂等、日志脱敏、备份泄密、恶意文件名、超大/截断/伪 PDF 响应、加密/损坏/超页数提取、提取取消与原子页替换、PDF backing canvas 上限、OCR 清单/分段下载/哈希/许可展示、惰性运行时、扫描页范围/置信度/原子写入、私网 DNS/重定向、下载取消与重启恢复、插件越权、正文提示注入、发布逐列白名单、跨表 canary、预览过期、不可变文件字节、HTML/JSON 注入、固定 Git 目标、主工作树不变性、非强制并发 push、worktree 注册路径清理、Pages 最小权限和供应链哈希必须有自动或可复现人工验收。

Agent 专项门禁还必须比较正常正文与包含 shell、凭据、MCP、插件、联网和改分指令的恶意正文，证明两者生成完全相同的进程能力参数；验证环境变量白名单、只读沙箱、MCP/工具关闭、外部研究显式开关和 Ollama 固定端点。视觉验收覆盖模型能力未知、策略关闭、文本充分、PDF 哈希冲突、页/像素/字节上限、取消和任务目录清理。成功报告与失败草稿之后，非空评分快照和运行候选排序行必须逐字节保持不变。

## 8. 更新检查边界

- 唯一网络目标是 `api.github.com/repos/Lisalsj/folioskiff/releases/latest`；请求禁环境代理、禁重定向、无 Authorization、无 cookie、无请求体，也不带设备 ID、用户路径、论文、偏好、凭据或安装标识。
- GitHub API 版本、媒体类型、User-Agent、超时、响应头和 512 KiB 正文上限固定。3xx 不跟随；限流、离线、5xx、错误 Content-Type、损坏 JSON 和超限响应只产生稳定状态，不把远端正文或本机异常返回页面。
- Release tag、正文摘要和资产名称中的版本必须一致并满足严格 SemVer。HTML 页面只能是 `https://github.com/Lisalsj/folioskiff/releases/tag/<tag>`；资产元数据只能指向同一仓库同一 tag。跨 host、内嵌凭据、端口、query、fragment、重复/越界名称或缺失 `release-manifest.json` 全部失败关闭。
- 变更与迁移是有长度、控制字符和 HTML 限制的纯文本；Vue 继续按文本渲染。能力矩阵和资产响应是关闭式投影，浏览器不接收 `browser_download_url`。
- 启动应用和打开设置时只读取本地更新记录。用户点击“立即检查”才联系 GitHub。检查和清除记录均受本地会话、Origin 与 CSRF 保护。
- “查看并更新”不是下载命令。页面先显示未签名警告、变更与迁移，二次确认后只用 `noopener,noreferrer` 打开再次校验的固定 GitHub Release；应用不存在下载、执行安装器或静默重启路径。

## 9. Windows 发行内容边界

- 构建子进程只继承 Windows 基础路径和临时目录等白名单变量，清除 `PYTHONPATH`，不继承 API key、Vite 私密变量、CUDA/自定义 DLL 路径或用户 Python site。依赖仅从锁定的 `packaging`、`models`、`ocr` extras 同步。
- 发行扫描以关闭式根布局和逐文件 SHA-256 为准，拒绝重解析点、大小写/Unicode 冲突、Python 字节码缓存、`.git`、数据库、凭据、备份、模型缓存、已知模型资产、模型权重后缀、构建根的 UTF-8/UTF-16 路径泄漏及未声明超大文件。错误只返回稳定代码和安全相对成员，不回显构建机绝对路径。
- frozen smoke 只继承 System32 PATH，明确验证 Python、Node 与 Git 均不可发现；状态、缓存和论文库进入隔离目录，程序文件临时设为只读。启动、HTTP、数据库和退出检查之后逐字节复核发行目录未被修改。
- 候选包只有扫描与 smoke 全部成功后才复制和原子提升。已存在发行目录先重命名为临时备份，新候选提升失败则恢复旧目录；staging 的暂时 Windows 文件锁采用有界重试，不允许以删除失败掩盖成功或留下包含本机路径的发布候选。

## 10. 安装、升级与卸载边界

- 便携 ZIP 关闭式拒绝绝对路径、盘符、反斜杠、`..`、非 NFC 名称、大小写冲突、重复成员、加密成员、链接、超量成员和超限字节；解压前可独立复核，解压后的程序目录不承担任何可变数据。
- Inno 固定每用户 AppId、Windows 11 x64 与 Local Programs；脚本没有 `[Registry]`、`[Dirs]`、`[UninstallDelete]` 或任意服务、任务、启动项、PATH、关联、防火墙写入入口。编译子进程不继承 API key、模型凭据、签名命令、`PYTHONPATH` 或任意 `ISCC` 环境覆盖。
- 安装器运行标记只表示“某个资料库锁拥有者正在运行”，不替代用户状态根的文件锁。安装器不自动关闭或重启应用；标记存在时安装/升级/卸载停止，程序字节和 SQLite 保持原状。
- 降级判断只读取固定 HKCU 卸载键的 `DisplayVersion`，无效版本按禁止降级处理。`PrepareToInstall` 的任何错误均形成 Inno 非零退出码；调用方只把精确 `0` 当成功，未来未知退出码一律失败关闭。
- 默认卸载不读取环境覆盖路径，也不删除数据库、凭据、自选论文库或迁移目录。可选清理只针对默认模型/cache/log、对象库和备份；研究数据必须显式勾选并逐字输入确认。根目录或任一子项为 reparse point、深度超过 64 或成员超过 100,000 时整棵跳过。
- 生命周期 smoke 在开始前要求固定卸载键不存在，避免覆盖真实安装；测试根只允许位于项目 `.tmp` 或系统临时目录。失败清理只有在注册的 `InstallLocation` 精确等于本次隔离安装根时才可删除该测试键，不能借测试脚本接管用户已有安装。

## 11. SBOM、摘要与签名边界

- 完整发行目录是十个普通文件的关闭式集合。验证器拒绝缺失、额外、重复、大小写冲突、符号链接/junction/reparse point、非 LF 文本、大小或 SHA-256 漂移；错误只暴露稳定分类与安全 basename。
- Python SBOM 只调用显式传入的实际冻结构建解释器，并核对其已安装项目版本。npm SBOM 只调用显式绝对 npm，以离线、`--package-lock-only`、`--ignore-scripts` 和隔离空 npmrc 读取锁文件；构建进程不继承代理、registry、token、认证、脚本或用户 npm 配置。
- 两份 CycloneDX 1.6 SBOM 必须通过官方严格 JSON schema，根组件、组件唯一性、许可证和完整依赖图均关闭式校验。无法识别的第三方许可证写为 `NOASSERTION`，不能伪造许可证名称。
- `SHA256SUMS.txt` 可证明用户拿到的字节与清单一致，但不能证明发布者身份、代码可信或 Microsoft SmartScreen 信誉；`UNSIGNED.md`、Release notes、manifest 与界面必须同时标明 v0.8 未签名。
- 默认构建不探测 SignTool、证书或网络时间戳。未来签名只有显式 `--enable-signing` 才读取单一 JSON argv 配置；可执行文件和目标占位符必须唯一且绝对，不使用 shell，PATH 只含签名器父目录，环境凭据与开发变量清空，签名前后重扫目标。v0.8 仍失败关闭任何 `signed=true` 结果。

## 12. v2 交互式 AI 与重置边界

PDF 提示注入属于首要输入威胁：论文正文、OCR、来源元数据、网页和模型输出都只能进入证据槽，不能成为系统指令、工具参数或权限决定。相关推荐与知识网站访问执行 SSRF 防护，拒绝回环、私网、链路本地、文件协议和重定向后的非公开目标。

每个任务冻结 `network_policy`；普通提问、解释和翻译为 `local_only`，只有用户在该次任务显式同意时才能使用 `external_research`。凭据始终在系统凭据库中，不进入 Assistant 会话、提示词、日志或诊断包。

“**重置本地数据**”先展示删除范围并要求确认，安全退出后再删除授权目录；凭据单独清除，任意自选路径、reparse point 或根目录校验失败都关闭操作。完整资产、攻击路径和**剩余风险**见 [v2 威胁模型](threat-model-v2.md)。

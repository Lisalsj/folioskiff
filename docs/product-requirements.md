# 产品需求与验收

## 1. 产品定义

`paper-reader` 是本地优先的个人研究 Agent。用户从模糊研究意图开始，经由“关键词确认、来源发现、可解释推荐、阅读与标注、按需分析、知识比较”形成可复现研究链路。产品首页是阅读简报与关注计划，不是搜索框。

## 2. 核心用户任务

1. 用自然语言描述研究问题，获得 12–24 个起步的中英双语关键词及可继续扩展的概念组。
2. 审阅差异并确认不可变关键词版本；未确认版本不能运行来源检索。
3. 选择固定起止月份或最近 N 个自然月、来源和来源特有过滤器，先看数量与样例再运行。
4. 在去重后的 Work 列表中查看相关性、质量、置信度、覆盖度及证据，给出显式反馈。
5. 阅读合法取得的 PDF，搜索、标注、保存进度，并在版本变化时确认标注迁移。
6. 主动点击分析，选择 Codex/Ollama、模型、推理强度、提示词、语言和证据范围，生成可复现报告。
7. 与单篇论文持续对话，或比较 2–10 篇论文；报告和聊天不能改变评分与排序。
8. 备份、恢复，或只把明确勾选且通过隐私白名单的内容发布到 `published` 分支。

## 3. v1.0 必须交付

- Windows 11 x64 安装器与便携 ZIP，干净机器无需 Python/Node。
- arXiv、OpenReview、Europe PMC、IEEE Xplore、Springer Nature 五个官方连接器及可恢复月份批次。
- 研究意图、关键词版本、来源预览、计划调度、去重审阅和部分成功。
- FTS5 与可降级的向量检索、四类独立分数、可编辑质量规则和偏好学习。
- 内容寻址论文库、PDF.js、PyMuPDF、按需 OCR、标注与版本迁移。
- Codex CLI、Ollama Local、Ollama Cloud；结构化报告、持久聊天、多论文比较。
- 备份恢复、隔离插件、精选发布、SBOM、SHA-256、更新提示。
- OpenAPI v1、可恢复 SSE、持久 Job、幂等命令和本地安全会话。

## 4. 明确不做

首版不迁移旧业务数据，不支持 macOS/Linux，不抓取 Google Scholar，不绕过付费墙，不执行个性化云端定时任务，不安装后台系统服务，不静默更新，不采集遥测，不提供团队账户、插件市场或无代码插件生成器。

## 5. 默认规则

- 默认时区为 `Asia/Shanghai`，可跟随系统或修改。
- 默认滚动最近 1 个自然月；超过 24 个月只警告，不禁止。
- 每批最多 50 个候选、默认推荐 20 篇；约 80% 利用、20% 可解释探索。
- 自动备份每周一次，保留 4 份；隐式原始事件保留 180 天；无保护且不喜欢的全文缓存 90 天后清理。
- 全文只在打开、收藏或分析时获取；受限内容由用户导入合法 PDF。
- OCR 与嵌入模型不随初始安装包分发，下载前展示大小、许可证、用途和哈希。

## 6. 最终性能与质量验收

测试数据规模为 20 万条元数据，硬件为 Windows 11 x64、16GB 内存、普通 SSD：冷启动不高于 8 秒，常用列表/检索 p95 不高于 800 毫秒，PDF 首屏不高于 2.5 秒，取消反馈不高于 2 秒。核心领域分支覆盖率不低于 90%，总体行覆盖率不低于 80%，界面满足 WCAG AA。

完整端到端验收必须覆盖首次启动、建计划、确认关键词、预览、部分失败恢复、阅读标注、按需分析、聊天、比较、备份恢复、精选发布、安装升级卸载和离线降级。

v0.5 的模型边界是：打开页面、PDF、报告标签、聊天标签或只读预检都不会调用模型；只有点击“开始分析”、发送非空问题或点击“生成比较报告”才创建 Agent Job。正文与模型输出始终视为不可信数据，Codex 使用只读沙箱且默认禁用联网与继承工具；视觉页只在用户允许、模型明确支持且文本确实依赖图表时按文档哈希发送。成功和失败均不得改写评分快照、推荐排序、反馈或旧正式报告。

v0.6 的平台边界是：备份不含凭据、模型、缓存、日志或旧备份；恢复只有在完整预检、第二次确认和重新启动后才原子应用。插件只在 Windows AppContainer + Job Object 可建立时运行，当前无插件市场或自动安装器。精选预览不产生 Git 或快照写入；确认后只发布用户所选白名单内容到固定的 `origin/published`，不推送 PDF、全文、批注、聊天、行为、偏好、凭据、完整提示词或失败草稿。真实外部 GitHub push、付费模型和云端生成不进入默认自动验收。

v0.9 的闭环边界是：显式收藏/喜欢/关注作者先形成用户可见的偏好词，用户可在建议前关闭或重新启用；Agent 给出的约 18 个双语词仍须人工修改并确认，研究意图和偏好上下文本身都不直接筛选。部分成功运行保留成功来源并允许重试失败来源；重要修订单列且不占新论文配额。切换排序或提交反馈不会创建分析任务，只有点击“分析”才进入预检。无 API key、无偏好历史、无模型时，免费来源和本地词法回退仍可完成主流程；未知质量显示为“未知”，内部保持中性 50，并明确降低覆盖度与置信度。

## 8. v2 个人研究工作流

v2 在既有发现、推荐、阅读和正式报告能力上增加四步首次配置与统一论文 Assistant。**四步首次配置**固定为存储与隐私、Agent、论文来源、阅读偏好；只有第一步必填，跳过其他步骤只产生可解释降级。

**统一论文 Assistant**把提问、解释、翻译和相关推荐放在同一阅读上下文中。翻译默认支持**英文到简体中文**并保留公式、引用和证据绑定；相关推荐先产生可修改的检索意图，用户确认后才访问学术来源。普通提问、解释和翻译默认本地证据范围，外部知识网站研究必须逐次获得用户的**显式同意**。正式分析报告仍是独立、点击触发、不可变的成果，不与对话消息混写。

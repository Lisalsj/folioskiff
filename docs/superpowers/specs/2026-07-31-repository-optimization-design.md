# paper-reader 仓库优化与 AI 阅读体验设计

> 状态：已确认设计，等待实施计划
> 日期：2026-07-31
> 范围：本地 `main` 分支，禁止推送
> 方法：分层原地重构，保留可靠能力并重建产品闭环

## 1. 背景

`paper-reader` 已经具备研究计划、五类论文来源、推荐与评分、PDF 阅读、OCR、标注、分析报告、论文聊天、多论文比较、备份、插件和精选发布等主要能力。当前问题不是缺少总体骨架，而是已有能力之间缺少清晰、简洁的用户闭环：

- 首次进入应用时，用户无法快速判断 Codex、Ollama、论文来源、API Key 和本地模型的可用状态。
- 设置集中在一个超长页面中，配置入口、诊断和修复方法不够清晰。
- 阅读器已有分析报告和聊天，但缺少选区驱动的解释、结构化翻译、相关论文和知识资源推荐。
- “本机 Codex CLI”和“完全本地模型”容易被混淆，当前错误分类也无法准确区分未安装、未登录和配置无效。
- 前端已有稳定的“安静图书馆”视觉语言，但存在巨型组件、路由未充分拆包、移动端导航弱和空状态语言不一致等问题。
- 仓库仍缺少完整的开源社区文件、项目元数据和一致的发布说明。
- JavaScript 开发工具链存在需要处理的高危传递依赖告警。
- GitHub Actions 的完整 Windows 工作流需要保留，同时应减少重复运行和无效消耗。

本设计不再次全量重写项目。实施将保留已经验证的领域能力和测试资产，通过明确边界、清理耦合和补齐交互闭环完成优化。

## 2. 已确认决策

| 主题 | 已确认选择 |
|---|---|
| 重构方式 | 分层原地重构 |
| AI 联网 | 普通提问、解释和翻译默认禁止联网；相关推荐和外部研究显式开启 |
| 首次使用 | 四步轻量向导，除数据目录外均可跳过 |
| 翻译范围 | 选中文本、当前页或章节、整篇论文 |
| 默认翻译方向 | 英文到简体中文，同时允许选择其他语言 |
| 推荐组织 | 相关论文和知识资源严格分栏 |
| 阅读器 AI | 一个统一助手，使用任务模式和显式上下文标签 |
| 默认 Agent | 本机 Codex CLI，Ollama Local 作为纯本地替代 |
| 推荐触发 | 不自动调用模型，用户点击后才运行 |
| GitHub Actions | 每个 PR 运行完整测试和 Windows 打包 |
| Git 实施位置 | 直接在本地 `main` 小步提交，不创建新的实施分支 |
| 历史数据 | 允许重建应用数据库，不维护旧业务兼容层 |
| 远端操作 | 本轮不推送 |

## 3. 产品目标

完成后，个人研究者应当能够：

1. 在全新 Windows 环境中完成安装并通过向导了解可用能力。
2. 在没有模型或付费来源 Key 的情况下导入、检索、阅读和标注论文。
3. 使用本机 Codex CLI 或 Ollama 对明确选择的论文证据提问。
4. 直接解释或翻译 PDF 选中文本，并能翻译页面、章节或全文。
5. 在显式请求后获得经过验证的相关论文和知识资源。
6. 始终知道 AI 读取了什么、是否联网、使用了哪个后端和模型。
7. 将正式报告、全文翻译和比较结果作为版本化研究产物保存和导出。
8. 在 AI、网络或单个来源失败时继续正常阅读和管理论文。
9. 从 README、首次使用文档和设置诊断中独立完成配置。
10. 以标准 GitHub 开源项目的方式报告问题、贡献代码、验证构建和发布版本。

## 4. 非目标

本轮不包含：

- 再次替换 FastAPI、Vue、SQLite 或现有本地服务架构。
- 引入 Electron、Redis、Celery 或独立数据库服务。
- 自动修改 Codex 全局配置或复制 Codex 凭据。
- 打开论文、翻页或选择文本时自动调用模型。
- 允许普通提问、解释或翻译静默联网。
- 让 Agent 修改论文评分、排序证据或用户反馈。
- 为旧应用数据库实现复杂的长期迁移兼容层。
- 推送提交、创建远端 PR 或发布 GitHub Release。
- 重新设计成营销落地页或普通搜索首页。

## 5. 总体架构

现有单体本地服务继续同时提供 Vue SPA 和 `/api/v1`。代码按六类能力边界整理。

### 5.1 论文来源层

负责：

- arXiv、OpenReview、Europe PMC、IEEE Xplore 和 Springer Nature。
- 查询编译、分页、月份范围、限流、重试和部分成功。
- 原始来源记录、字段级来源和抓取时间。
- 来源特有过滤器和只读 live smoke。

来源层不得直接写入 AI 会话、用户反馈或论文评分。

### 5.2 论文领域层

负责：

- `Work` 稳定身份。
- `SourceRecord`、`DocumentVersion` 和版本关系。
- PDF、提取文本、OCR、标注、书签和阅读进度。
- 论文库、收藏、喜欢、不喜欢和置顶。
- 去重、评分证据、偏好与排序。

该层不依赖具体 Agent 后端。

### 5.3 发现与推荐层

负责：

- 研究意图。
- 不可变关键词版本。
- 日期范围、来源范围和运行计划。
- 本地关键词、全文检索和语义匹配。
- 本地探索提示和推荐排序。

Agent 可以提出研究关键词和检索意图，但只有用户确认的关键词版本能够执行检索。

### 5.4 AI 阅读任务层

统一支持四种任务模式：

- `ask`
- `explain`
- `translate`
- `related`

每个任务必须显式记录：

- `work_id`
- `document_version_id`
- 内容哈希
- 上下文范围
- Agent 后端
- 模型
- 推理强度
- 输出语言
- 联网策略
- 提示词模板版本
- 幂等键
- 任务和执行状态

### 5.5 正式研究产物层

负责：

- 单篇分析报告。
- 多论文比较报告。
- 全文翻译。
- 精选发布快照。

这些产物不可被日常聊天覆盖。每个版本都绑定输入文档哈希、模型、提示词、证据范围和生成时间。

### 5.6 平台与安全层

负责：

- 持久任务状态机。
- SSE 和轮询恢复。
- 本地会话、Origin 和 CSRF。
- 设置和能力检测。
- 系统凭据库引用。
- 备份、恢复、插件隔离和日志脱敏。

## 6. 首次使用与设置中心

### 6.1 四步首次向导

#### 第一步：本地空间与隐私

- 选择论文库和备份目录。
- 数据目录是唯一必须确认的项目。
- 说明哪些数据只保存在本机。
- 说明本机 Codex CLI 可能连接云端模型。

#### 第二步：AI 能力检测

- 检测 Codex CLI 是否安装。
- 检测 Codex 登录状态。
- 检测 Codex 配置是否有效。
- 检测 Codex CLI 版本兼容性。
- 检测 Ollama 可执行文件和本地服务。
- 探测可用模型。

错误必须分类为：

- 未安装
- 未登录
- 配置无效
- 服务未启动
- 版本不兼容
- 探测超时
- 未知错误

应用提供脱敏诊断和用户可执行的修复指引，但不得修改外部配置。

#### 第三步：论文来源

- 免费来源可以直接启用。
- 需要 Key 的来源显示用途、申请入口、配置状态和验证按钮。
- 缺少 Key 不阻止进入应用。
- 不使用聚合器伪装成未配置的官方来源。

#### 第四步：阅读偏好

- 默认报告和翻译语言为简体中文。
- 设置默认 Agent、模型、推理强度、主题和时区。
- 可选输入初始研究兴趣。
- 所有项目都允许跳过。

### 6.2 设置中心

设置页拆成独立子路由：

- 配置概览
- AI 与模型
- 论文来源
- 阅读与翻译
- 推荐与评分
- 存储与备份
- 插件与扩展
- 更新、诊断与关于

配置概览聚合状态和待处理问题。每个设置分区独立保存，验证错误靠近对应字段，离开未保存页面时提示。

## 7. 前端信息架构与视觉

### 7.1 主导航

桌面端：

- 阅读简报
- 关注计划
- 我的论文库
- 多论文比较
- 精选发布
- 设置

移动端：

- 简报
- 计划
- 论文库
- 更多

移动端入口必须同时显示图标和文字。比较、发布和设置放入“更多”。

### 7.2 阅读简报

首页继续作为 Agent 阅读简报，不改成搜索框首页。内容包括：

- 关注计划更新。
- 当前批次推荐。
- 最近阅读。
- 待继续任务。
- 首次配置状态。
- 本地探索提示。

空状态、错误和后端消息统一为用户可理解的中文。

### 7.3 “安静图书馆”设计系统

保留：

- 暖纸色背景。
- 深森林绿主色。
- 克制酒红强调色。
- 衬线标题。
- 高可读无衬线正文。

设计参数：

- 变化度约 4/10。
- 动效约 2/10。
- 信息密度约 5/10。

不引入第二套组件库。继续使用 Reka UI 无样式无障碍原语和项目自有 tokens。避免过多卡片、胶囊、渐变和装饰动效。

## 8. 阅读器与统一 AI 助手

### 8.1 阅读器布局

桌面端继续三栏：

- 左侧：论文库和目录。
- 中间：PDF 阅读器。
- 右侧：标注、AI 助手和正式报告。

中等宽度将论文库折叠为抽屉。移动端在 PDF、AI 和标注之间切换并保持阅读位置。

### 8.2 前端组件边界

阅读工作台至少拆为：

- `LibraryPane`
- `DocumentViewer`
- `ContextActionBar`
- `ResearchSidebar`

AI 助手至少拆为：

- 任务模式切换。
- 上下文选择器。
- 联网状态。
- 对话时间线。
- 结构化任务卡。
- 统一输入框。
- 可折叠模型设置。
- 引用与证据抽屉。

后端、模型和推理强度属于低频设置，默认折叠。选中文本后的操作条只保留解释、翻译、引用到提问和保存标注。

正式分析报告仍由独立的“分析”按钮触发。点击前不调用模型；点击后显示紧凑预检，确认后端、模型、推理强度、语言、提示词、证据等级和联网范围。报告和日常助手共享底层 Agent 适配器，但不共享可变的结果记录。

### 8.3 上下文范围

可选择：

- 选中文本。
- 当前页。
- 当前章节。
- 整篇论文。
- 我的标注。

用户发送前必须看到实际上下文。章节无法可靠识别时，UI 使用明确的页码范围回退，不能伪装为已识别章节。

## 9. 提问与解释

- 默认只使用选定论文内容和本地元数据。
- 回答引用 PDF 页码、章节、图、表或公式。
- 区分作者原文、AI 解释和不确定推断。
- 证据不足时明确说明。
- 不得自动联网补充。
- PDF 正文视为不可信输入，不能覆盖系统指令。

## 10. 翻译

### 10.1 范围

- 选中文本。
- 当前页。
- 当前章节。
- 整篇论文。

### 10.2 默认行为

- 默认英文翻译为简体中文。
- 允许选择其他源语言和目标语言。
- 选区和页级翻译流式返回。
- 章节和全文翻译使用可取消、可恢复的后台任务。
- 原 PDF 永不覆盖。

### 10.3 质量约束

- 保留公式、变量、引用编号、图表编号和代码块。
- 建立论文级术语表。
- 记录 OCR 页级和区域级置信度。
- 对低置信度 OCR 译文给出明确提示。
- 整篇翻译保存原文和译文的段落映射。
- 已生成译文可以作为后续提问或解释的显式上下文，但不能无提示地替代原文证据。

### 10.4 双语阅读与导出

- 只看中文。
- 只看英文。
- 原文和译文对照。
- 导出 Markdown。
- 导出 HTML。
- 浏览器打印 PDF。

## 11. 相关推荐与知识资源

### 11.1 触发

- 打开论文、翻页和阅读时不自动调用模型。
- 本地规则可以显示一条克制的探索提示。
- 用户点击“相关推荐”后才创建 Agent 任务。
- 用户确认或修改检索意图后才执行。

### 11.2 相关论文

优先使用已配置的学术连接器。每项结果包含：

- 标题、作者、年份和来源。
- DOI 或来源 ID。
- 与当前论文的关系。
- 匹配证据。
- 可信度。
- 论文库状态。

结果进入统一 `Work` 去重流程。无法验证身份的结果不能静默合并。

### 11.3 知识资源

仅在用户显式启用外部研究时运行。优先：

- 官方文档。
- 高质量综述。
- 大学课程。
- 教材页面。
- 可信学术数据库。

每项包含：

- 页面标题。
- 来源域名。
- 资源类型。
- 推荐理由。
- 访问日期。
- 可验证链接。

论文和网站结果严格分栏。无法验证 DOI、来源 ID 或 URL 的条目被排除或标记为待核验。

## 12. Agent 后端

### 12.1 Codex CLI

- 默认后端。
- 调用用户电脑上的 Codex CLI。
- 复用 Codex 自身登录状态。
- 不复制凭据。
- 不修改 `~/.codex/config.toml`。
- 使用只读隔离工作目录。
- 普通任务关闭网络。
- 外部研究任务显式开启网络。

“本机 CLI”与“云端模型处理”必须在 UI 中明确区分。

### 12.2 Ollama

- Ollama Local 作为纯本地替代。
- 动态探测本地模型。
- 服务未启动时显示准确状态。
- Ollama Cloud 如保留，凭据只进入系统凭据库，并在界面中明确标记为云端后端。

### 12.3 结构化输出

- Codex 使用结构化输出约束。
- Ollama 在支持时使用 schema。
- 解析失败允许一次修复重试。
- 仍失败则保存失败草稿和诊断，不生成正式产物。

## 13. 数据模型

### 13.1 `AssistantSession`

- 每个 `Work` 一个持久会话。
- 保存会话设置和最后使用时间。

### 13.2 `AssistantTask`

- 表示一次 `ask`、`explain`、`translate` 或 `related`。
- 保存任务状态、幂等键、上下文范围、联网策略和关联 Job。
- 重试创建新的执行记录，不覆盖旧结果。

### 13.3 `ContextSnapshot`

- 不可变。
- 绑定 Work、文档版本、内容哈希、页面范围、选区和标注。
- 保存证据摘要和提取版本。

### 13.4 `AgentRun`

- 保存后端、模型、推理强度、提示词版本、联网权限和结构化诊断。
- 不保存凭据。

### 13.5 `AssistantMessage`

- 保存用户消息、流式回答、引用和关联任务。
- 原始消息永久保留。
- 压缩检查点独立存储。

### 13.6 `TranslationArtifact`

- 绑定文档版本和翻译方向。
- 保存段落级原文、译文、页码、术语表、OCR 置信度和版本。
- 完成前保持草稿状态。

### 13.7 `RelatedResourceSet`

- 保存检索意图、确认关键词和覆盖范围。
- 论文条目和知识资源条目分别存储。
- 记录验证状态、来源、访问时间、理由和可信度。

现有 `AnalysisReport`、`ComparisonReport`、`ScoreSnapshot` 和 `LibraryState` 保持独立。

## 14. API 与任务恢复

API 继续以 Pydantic/OpenAPI 为事实来源并生成 TypeScript 类型。新增或整理：

- `/onboarding`
- `/assistant/sessions`
- `/assistant/tasks`
- `/assistant/context`
- `/translations`
- `/related-resources`
- `/settings/agents`
- `/jobs`
- `/events`

长任务返回 HTTP 202。相同幂等键返回原任务。

流式规则：

- 片段先持久化，再发送 SSE。
- 事件具有连续序号。
- 支持 `Last-Event-ID`。
- SSE 不可用时回退轮询。
- 取消操作应在两秒内反馈状态。
- 底层进程仍在退出时显示“正在停止”，不伪装成已经取消。

## 15. 数据重建

本轮不为旧业务数据建立长期兼容层。

检测到旧数据库时：

1. 创建本地快照。
2. 展示将被重建的数据类型。
3. 等待用户确认。
4. 创建新数据库、FTS 和向量索引。
5. 将旧目录保留为只读备份。

原始 PDF 不得静默删除。开发环境提供可重复生成的种子数据和来源 fixtures。

## 16. 前端性能与可访问性

目标：

- 主应用初始 JavaScript 低于 350 KB。
- PDF.js、OCR 和大型阅读器功能按需加载。
- Reader、比较、发布和设置使用独立路由 chunk。
- 长列表使用分页或虚拟化。
- 流式 token 批量渲染。
- 不让移动导航遮挡 PDF 或页面按钮。

测试视口：

- 桌面。
- 中等宽度。
- 手机。

每个主要页面必须实现：

- 加载状态。
- 空状态。
- 部分成功状态。
- 错误状态。
- 离线或后端不可用状态。

键盘、焦点、对比度、屏幕阅读器和降低动画达到 WCAG AA。

## 18. Git 与 GitHub Actions

### 18.1 本地 Git

- 直接在本地 `main` 实施。
- 不重写历史。
- 不变基。
- 不强制重置。
- 不暂存 `.rc`、`.w`、`AGENTS.md` 或其他用户文件。
- 使用 Conventional Commits。
- 每个阶段形成独立可回滚提交。
- 不推送。

### 18.2 GitHub Actions

每个 PR 执行：

- Ruff。
- Mypy。
- pytest 和覆盖率。
- Vitest。
- TypeScript 严格检查。
- 前端生产构建。
- Playwright 关键流程。
- npm audit。
- Python 依赖审计。
- Windows 安装器和便携包构建。
- 安装包 smoke test。
- SBOM 和 SHA-256。

降低浪费但不降低范围：

- 同一 PR 新运行取消旧运行。
- 缓存 uv、Python、npm 和 Playwright。
- 测试结果在同一工作流复用。
- 打包不重复执行相同测试。
- 真实 Key 的 smoke test 保持手动和只读。
- Release 仅由版本标签触发。

GitHub Actions 额度不可用时，本地脚本必须能够执行同等门槛。

## 19. 安全与依赖

当前 JavaScript 开发工具链的高危传递依赖需要在首个阶段修复，包括：

- [`brace-expansion` 公告](https://github.com/advisories/GHSA-mh99-v99m-4gvg)
- [`js-yaml` 公告](https://github.com/advisories/GHSA-52cp-r559-cp3m)

处理顺序：

1. 优先升级直接依赖。
2. 必要时使用精确 `overrides`。
3. 更新锁文件。
4. 运行完整测试和构建。
5. 禁止未经审查的 `npm audit fix --force`。

安全回归覆盖：

- 回环绑定。
- Origin 和 CSRF。
- 路径穿越。
- 日志和凭据脱敏。
- 插件权限。
- PDF 提示注入。
- 外部链接验证。
- Codex 错误分类。

## 22. 最终验收

以下场景全部通过才可完成：

- 全新 Windows 用户无需 Python 或 Node 完成安装和首次配置。
- Codex 未安装、未登录、配置无效和版本不兼容分别得到准确提示。
- 无 AI 后端时仍能导入、检索、阅读和标注论文。
- PDF 选中文本可以直接解释或翻译。
- 整篇翻译支持取消、重启和恢复。
- 普通提问、解释和翻译不联网。
- 相关推荐只在用户点击后执行。
- 外部研究持续显示联网状态和来源。
- 相关论文可加入论文库并正确去重。
- 无法验证的论文或网站不会显示成可靠结果。
- AI 失败不会改变评分、排序或正式报告。
- 移动端可在 PDF、AI 和标注之间切换并保持阅读位置。
- 安装器、便携包、SBOM、哈希、文档和源码一致。
- Python 和 npm 不存在未说明的已知漏洞。
- 全部测试、类型检查、构建和可访问性门槛通过。
- Git 工作树只包含预期修改。
- 没有执行推送。

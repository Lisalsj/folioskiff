# v0.9 RC 性能、安全与无障碍实施计划

> **执行要求：** 产品闭环计划全部通过后执行。使用 `superpowers:systematic-debugging` 定位每个失败，使用 `superpowers:test-driven-development` 修复；不使用子代理。

**目标：** 在不削弱数据、隐私或解释性的前提下达到 v1 性能门槛，并完成故障注入、安全、无障碍和干净 Windows 验收。

**目标环境：** Windows 11 x64、16 GB 内存、普通 SSD、20 万 Work 元数据。开发机或 hosted runner 数据只作为诊断；最终门槛必须记录机器信息、数据生成种子、命令、原始样本和 p95。

## Task 1：20 万论文库 SQL 分页与 FTS 检索

**创建：**

- `scripts/benchmark_library.py`
- `tests/performance/test_library_queries.py`
- `docs/performance-baselines.md`
- `src/paper_reader/migrations/versions/0031_library_query_indexes.py`

**修改：**

- `src/paper_reader/reader/repository.py`
- `src/paper_reader/recommendation/lexical.py`
- `tests/reader/test_library_repository.py`
- `tests/reader/test_library_api.py`

1. 先保存 RED 基线：固定 seed 生成 20 万 Work、LibraryEntry、LibraryState 和少量 DocumentVersion；分别测无查询列表、中文标题、英文作者和 DOI，输出每次时延与 `EXPLAIN QUERY PLAN`。
2. 将 queryless 路径改为 SQL `COUNT + ORDER BY + LIMIT/OFFSET`，禁止先 materialize 全库。
3. 查询路径使用 work FTS5 候选和 DOI 精确/前缀分支；输入经关闭式 FTS 转义，不能把用户字符串直接拼入 SQL。
4. 对一页 Work 批量加载 LibraryState 和 DocumentVersion，消除逐项 N+1；代表版本选择规则保持“合法、最新、最完整”。
5. 通过只追加的 `0031_library_query_indexes.py` 添加需要的复合索引并验证 SQLite 实际采用；不得回改已执行的 `0030`。迁移前后结果顺序、分页 total、Unicode/DOI 搜索一致。
6. 单元门禁要求固定 20k 小样不出现全表 Python 筛选；20 万外部门禁要求常用列表/检索 p95 ≤800 ms。
7. 记录优化前后证据，提交 `perf(library): paginate and search in sqlite`。

## Task 2：模糊去重候选收敛与跨来源一致性

**创建：**

- `tests/performance/test_identity_candidates.py`

**修改：**

1. 先写 RED：20 万 Work 下无 DOI ingest 不得遍历全部 active Work；测试通过计数器/查询计划证明候选上限关闭。
2. 先查 DOI；无 DOI 时用规范标题 token/FTS 和作者键取得有限候选，再运行现有 SequenceMatcher。候选为空可创建新 Work，不能为了性能静默降低已知高相似召回。
3. 为边界样例建立金样：标点/大小写/中英文空格、作者顺序、标题轻微改写、不同 DOI 冲突、完全不同标题；低置信度继续进入人工审阅。
4. FTS 不可用时使用有界 SQL 前缀/年份候选并标记退化；不得回退全库扫描。
5. 20 万 ingest p95 和候选数量写入性能文档；提交 `perf(identity): bound fuzzy matching candidates`。

# v0.6 Platform Implementation Plan

> 执行要求：由当前主代理按任务顺序实施，不启用子代理。每个任务必须遵循
> RED → 最小实现 → GREEN → 回归 → 文档同步 → Conventional Commit；不得以
> 跳过测试、放宽断言或静默降级绕过安全边界。

## 目标

交付三个彼此隔离、但共享持久 Job 与本地安全会话的能力：

1. 可验证、可恢复、默认每周执行且保留 4 份的本地备份；支持手动便携导出和
   可选密码加密，凭据永不进入包。
2. 通过 Python entry point 发现、但只在受限子进程运行的插件 SDK；固定
   `SourceConnector`、`MetadataEnricher`、`ScoreDimension`、`AgentBackend`、
   `Publisher` 五个扩展点。
3. 先经隐私白名单冻结 `PublishedSnapshot`，再通过临时 Git worktree 只向
   `published` 分支发布精选列表/报告；`main` 不产生个性化文件。

v0.6 不提供插件市场、无代码插件生成器、团队发布、后台系统服务、静默恢复或
云端备份。真实 Git push 只在用户明确点击后发生；自动化测试只使用临时本地
仓库和本地 bare remote。

## 已锁定的实现决策

### 备份包与一致性

- 便携包格式为 `paper-reader-backup-v1`。未加密包是 ZIP；加密包使用固定
  `PRBENC1` 头、Scrypt 派生的 256 位密钥和流式 AES-256-GCM，规范头作为
  AAD，16 字节认证标签写在文件末尾。密码只进入进程内一次性 secret lease，
  不进入 Job、SQLite、日志、错误、事件或备份清单。
- 数据库通过 Python `sqlite3.Connection.backup()` 取得 WAL 一致性快照；该
  API 在数据库被其他连接访问时仍可工作：
  <https://docs.python.org/3.12/library/sqlite3.html#sqlite3.Connection.backup>。
- 包只包含数据库快照和该快照中合法引用的内容寻址 PDF。模型、OCR 模型、
  日志、缓存、临时目录、旧备份、诊断包、系统凭据库和环境变量全部排除。
- `manifest.json` 使用规范 JSON，记录格式/应用/schema 版本、数据库与对象的
  相对归档名、大小和 SHA-256、包含/排除范围及创建时间；包和 manifest 另有
  SHA-256。对象必须仍符合 `objects/aa/bb/<sha>.pdf`，不接受符号链接、junction、
  哈希/大小变化或越界路径。
- 恢复不直接覆盖正在运行的应用。上传包先流式落到内部随机目录，再验证加密
  标签、ZIP 中央目录、重复/大小写冲突名、绝对路径、`..`、反斜杠、链接、
  member/总大小、清单和逐文件哈希。Python 文档同样要求调用者对不可信 ZIP
  路径做显式校验：<https://docs.python.org/3.12/library/zipfile.html>。
- 验证通过后，数据库与对象分别暂存到与最终目标相同的文件系统。用户第二次
  明确确认只写入无密码的 `pending-restore.json`；下次启动在数据库打开前执行
  双根目录恢复 journal。当前数据库/对象先原子改名为 rollback，任一步失败都
  还原两边；只有新数据库 `quick_check`、清单哈希和对象复核全部通过才提交。
- 恢复后的所有 `queued/running` Job 必须转为稳定的
  `restored_interrupted` 失败状态，禁止从旧快照自动恢复网络、Agent、下载、
  OCR、插件或发布副作用。完成迁移并成功启动后写入 `RestoreReceipt`。
- 只允许格式 v1 和当前 Alembic 可识别的同代或祖先 revision；未来应用版本、
  未知 revision、损坏/截断包和错误密码在改变现有数据前失败。
- 每次真正 schema 升级前先在 `state_root/migration-snapshots` 用 SQLite backup
  建立数据库快照、manifest 与哈希；升级成功后只保留最近 4 份。迁移快照不
  复制内容文件，因为迁移不得修改内容寻址对象。
- 自动备份只在应用打开时检查，每 6 小时最多检查一次；首次启用时间持久化为
  调度锚点，首次满 7×24 小时或距最近成功自动备份满 7×24 小时才创建任务。
  自动备份保留最近 4 份，手动导出不自动删除。

### 插件进程与权限

- 主进程只调用 `importlib.metadata.entry_points(group="paper_reader.plugins")`
  读取 name/value/distribution 元数据，绝不调用 `EntryPoint.load()`。Python
  3.12 的 selectable entry point 契约见：
  <https://docs.python.org/3.12/library/importlib.metadata.html#entry-points>。
- entry point 的模块/属性只交给独立 worker 解析。生产 Windows 使用
  AppContainer 限权令牌、Job Object、隐藏窗口、随机空工作目录、环境变量白名单
  和继承的 stdin/stdout pipe；创建 AppContainer 或 Job Object 失败时插件不可用，
  不回退到普通子进程。非 Windows 仅支持测试注入，不宣称 v1 兼容。
- 插件进程永远不获得直接网络 capability。声明并经用户批准的域名访问由主进程
  固定 HTTP broker 代办，并沿用 DNS/重定向/大小/超时/凭据边界；文件和凭据也
  只通过 host broker 的明确 resource ID 访问。未批准、版本/manifest 哈希变化、
  任意路径、私网地址或未声明资源一律拒绝。
- stdin/stdout 采用逐行 UTF-8 JSON。请求信封固定包含 `protocol_version`、
  `request_id`、`capability`、`method`、`payload`、`deadline`；响应增加
  `ok` 与 `payload` 或结构化 `error`。流式事件具有单调 sequence，最终响应只能
  出现一次。单行、总输出、stderr、请求数、墙钟时间和子进程树均有上限。
- manifest 必须声明稳定 plugin ID、显示名、distribution/version、协议范围、
  五类能力、每类方法、JSON Schema 配置、请求的 network/file/credential 权限。
  配置 schema 禁止远程 `$ref`、可执行默认值和未知格式。
- 连续 3 次超时、崩溃、乱码、超限或协议错误会熔断该 manifest 版本；只禁用该
  插件，不影响主应用或其他插件。用户可查看原因并显式重置。新 distribution
  版本或 manifest 哈希必须重新审批权限。
- v0.6 示例插件是无网络 fixture `SourceConnector`，用于 SDK、分页、deadline、
  部分失败和打包契约；不把示例结果伪装为真实来源。

### 精选发布与 Git

- 发布输入只允许标题、公开说明、明确排序的 Work、用户选择的正式报告版本和
  用户专门填写的公开导语。服务端重新读取规范 Work/报告，不接受客户端提交的
  任意报告正文或分数。
- 白名单可包含论文题名、作者、摘要、DOI、公开来源链接、发表/更新时间、冻结
  的四类分数/覆盖/置信和安全渲染后的正式报告；明确拒绝 PDF/全文、批注/私有
  笔记、聊天、隐式事件、偏好、凭据、文件路径、完整提示词、失败草稿、原始模型
  输出和未选报告。
- 预览是只读纯函数，返回确切 payload、文件清单、排除说明和 fingerprint，不
  创建 snapshot/Job。只有带当前 fingerprint、CSRF 与幂等键的确认命令才冻结
  不可变 `PublishedSnapshot` 并创建 `publishing.publish` Job。
- 内置 Git publisher 只接受用户配置并再次确认的本地 Git 仓库、无内嵌凭据的
  GitHub HTTPS `origin` 和固定目标 `published`。Git 通过 argv 调用，不使用 shell，
  不读取/存储 PAT；认证完全交给用户现有 Git Credential Manager。
- 每次发布从最新 `origin/published` 建立 detached 临时 worktree；远端分支不存在
  时建立空 orphan 历史。Git 官方支持 detached/orphan worktree 及显式 remove：
  <https://git-scm.com/docs/git-worktree>。生成内容只在经过绝对路径校验的
  `cache_root/publishing-worktrees/<job>` 内写入。
- 发布前后逐字节记录主工作树 `HEAD`、分支、tracked/untracked porcelain 状态；
  任一变化视为失败。推送只允许快进 `HEAD:refs/heads/published`，不 force、不
  删除分支；并发更新失败后重新 fetch/预览再重试。
- 静态站点由 Python 确定性渲染，不需要 Node；生成 CSP、无外部脚本的 HTML、
  JSON snapshot、索引与 Pages workflow。workflow 使用 GitHub 官方 Pages artifact
  流程及 `pages: write`/`id-token: write`：
  <https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages>。
- 成功、失败和取消都调用 `git worktree remove`；只对注册且位于专用 cache 根内
  的路径清理，随后 `worktree prune --dry-run` 验证无本任务残留。失败可从冻结
  snapshot 重试，不需要保留临时 worktree。

## 数据与 API

### 新表

- `backup_archives`：成功的自动/手动包、Job、格式/应用/schema 版本、相对备份
  路径、大小、package/manifest SHA-256、加密标记、对象数、创建/删除时间。
- `backup_schedule_state`：单例每周调度锚点；防止首次启动立即备份，也防止重启
  不断重置首次七天等待期。
- `restore_receipts`：成功启动后写入的源包哈希、源版本、对象数、恢复/迁移结果
  和时间；不保存上传路径、密码或 rollback 路径。
- `plugin_installations`：entry point/distribution 身份、manifest/哈希、启用状态、
  连续失败、熔断原因、最近发现/调用时间。
- `plugin_permission_decisions`：按 plugin+distribution version+manifest hash 只追加
  grant/revoke 决定，保存 permission kind、规范 resource 与决定时间，不保存凭据值。
- `publishing_settings`：单例 Git 仓库、remote 名、已核验公开 remote URL 与更新时间。
- `published_snapshots`：不可变版本、slug/标题/公开导语、明确选择、白名单 payload、
  文件 manifest、payload/fingerprint SHA-256、创建时间。

迁移顺序固定为 `0023_backup_archives`、`0024_plugin_registry`、
`0025_published_snapshots`。

### 路由

- `/api/v1/backups`：能力/列表、手动创建、自动策略状态、包下载。
- `/api/v1/backups/restore-packages`：上传并创建验证 Job；密码只进入内存 lease。
- `/api/v1/backups/restore-previews/{id}`：读取验证结果与确切恢复范围。
- `/api/v1/backups/restores`：确认当前 fingerprint 并创建待重启恢复 Job。
- `/api/v1/plugins`：发现、能力/manifest、健康、配置、权限决定、启用/禁用/重置。
- `/api/v1/publishing/settings`：Git 能力探测与明确配置。
- `/api/v1/publishing/previews`：纯只读白名单预览。
- `/api/v1/publishing/snapshots`：确认并创建 202 发布 Job、列表/详情/重试。

所有变更路由继续要求本地会话、回环 Origin、CSRF；长任务要求
`Idempotency-Key` 并返回 HTTP 202。下载、预览和插件错误响应使用
`private, no-store`，不返回绝对路径、密码、secret、Git 凭据或插件 stderr。

- 备份可以在 WAL 写入期间取得一致快照，包中只有数据库和被数据库引用的合法
  内容对象；凭据、模型、日志、缓存和旧备份从 member、manifest 与原始字节中
  全部缺席。
- 错误密码、损坏/截断/未来包、空间不足和恢复任一 phase 失败都不会留下数据库
  与对象树混合状态；金样恢复后计划、偏好、批注、报告、聊天、比较、版本关系
  和 PDF 哈希一致，凭据仍为空。
- 每周自动备份仅在应用打开时执行并保留 4 份；手动导出、加密、下载、取消、
  重试和待重启恢复对用户可见、可解释。
- 主进程不导入插件；生产插件只能在可用的 Windows 限权 sandbox 中运行。默认
  无网络/文件/凭据，所有授权可审计，失败/超时/越权/协议错误只熔断单个插件。
- 五类插件适配契约可调用，示例 SourceConnector 通过独立安装契约，但不会冒充
  内置真实来源或绕过现有评分/Agent/凭据边界。
- 发布前可看到确切白名单 payload 与文件；PublishedSnapshot 不含 PDF、私有
  笔记、聊天、行为、偏好、凭据、路径或完整提示词。
- 发布成功和任何失败路径都不改变主工作树；只向 `published` 快进推送，临时
  worktree 可验证清理，Pages workflow 使用最小权限。
- 所有自动化、安全、无障碍、视觉和文档门禁通过后才把 v0.6 标记完成并进入
  v0.8 Packaging；持续目标仍保持 active，直到 v1.0 全部验收完成。

# v0.8 Packaging 可执行 TDD 计划

更新日期：2026-07-14

## 1. 目标与不可变边界

把已经通过 v0.6 验收的应用交付为 Windows 11 x64 每用户安装器和便携 ZIP。两种产物都必须在没有 Python、Node.js、Git 或开发仓库的环境中启动本地服务并打开浏览器；用户数据、凭据和下载模型不得写入只读安装目录。

本里程碑固定以下决策：

- 使用 PyInstaller `onedir`，不使用 `onefile`。安装器和便携 ZIP 复用同一组经过扫描的字节，避免每次启动解压并满足冷启动目标。
- 安装器采用 Inno Setup、固定 AppId 和 `PrivilegesRequired=lowest`，默认安装到当前用户的 Local Programs；升级只替换程序文件。
- 安装版与便携版都继续遵守稳定数据边界：状态/日志/模型缓存位于 `%LOCALAPPDATA%\paper-reader`，论文库和备份位于 Documents 下或用户选择的目录。便携仅表示程序文件无需安装，不表示把私有数据塞进 ZIP 目录。
- 基础产物包含 FastEmbed、sqlite-vec、ONNX Runtime 和 RapidOCR 运行时，使无 Python 环境仍能按需启用能力；基础产物不得包含任何 E5/OCR 权重、用户模型缓存或构建机模型缓存。
- 单实例以用户 profile 内保持打开的 Windows 文件锁为唯一所有权事实；状态 JSON 只负责激活，不得被当作锁。进程退出后内核自动释放锁，旧状态文件不能授权第二个服务访问数据库。
- 第二次启动只请求现有实例签发新的短期一次性 bootstrap 入口并打开浏览器；绝不复用已消费 token，不启动第二个数据库引擎。
- 更新检查只读取 `api.github.com/repos/Lisalsj/folioskiff/releases/latest` 及该 release 的固定清单；不静默下载、不执行安装器、不上传版本或设备标识。用户确认后仅打开 HTTPS release 页面。
- v0.8 首版不做 Authenticode；界面、发行说明和产物清单必须显式标为未签名，同时保留参数化签名 hook。
- 构建 fixture、假下载、临时 GitHub Release 响应和本地 HTTP 服务都不是 live 能力。默认 CI 不访问模型源、不调用付费模型、不发布 Release。

官方实现依据：

- [PyInstaller spec 与数据文件](https://pyinstaller.org/en/latest/spec-files.html)、[运行时资源定位](https://pyinstaller.org/en/stable/runtime-information.html)、[Windows 版本资源](https://pyinstaller.org/en/stable/usage.html#capturing-windows-version-data)
- [Inno Setup 非管理员安装](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm)、[固定 AppId](https://jrsoftware.org/ishelp/topic_setup_appid.htm)、[编译器退出码](https://jrsoftware.org/ishelp/topic_compilercmdline.htm)
- [Windows 单实例锁建议](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createmutexw)
- [GitHub Latest Release API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)
- [CycloneDX Python](https://cyclonedx-bom-tool.readthedocs.io/en/latest/usage.html) 与 [npm SBOM](https://docs.npmjs.com/cli/commands/npm-sbom/)

# v1.0 冻结与发布实施计划

> **执行要求：** 只有产品闭环和 RC 质量计划全部通过后执行。每次宣称完成前使用 `superpowers:verification-before-completion`；分支收尾使用 `superpowers:finishing-a-development-branch`。不使用子代理。

**目标：** 冻结兼容面，构建同源、可验证的 Windows 11 x64 v1.0 发行物，完成真实生命周期验收并发布。

**禁止提前完成：** 不能因测试数量、版本号、tag、draft Release 或文档存在而宣称 v1.0。任一核心验收失败都回到 RED → GREEN → 全量复验。

## Task 3：阻断缺陷收敛循环

**创建：**

- `docs/rc-blockers.md`

**修改：**

- 每个失败对应的最小源文件和回归测试

1. 把自动、人工、性能、VM 和 live smoke 失败按 P0/P1/P2 记录：复现条件、用户影响、证据、负责人（当前主代理）和状态。
2. P0/P1 必须全部修复；核心验收不能降级为 known issue。每个修复先保留失败测试或 fixture，再做最小实现。
3. 修复后先跑精确测试，再跑领域测试；每日/每批结束跑完整门禁，避免多个未验证修复叠加。
4. 所有 blocker 关闭后，从干净 checkout 和新数据目录再跑一次完整矩阵，旧成功日志不复用。
5. 每个提交使用 `fix(rc): ...`；最终 `docs/rc-blockers.md` 保留关闭证据但不包含 secret、用户路径或论文内容。

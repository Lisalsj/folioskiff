# v0.4 Reader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:executing-plans` to implement this plan task-by-task. The
> repository owner has selected single-primary-agent execution, so do not
> dispatch subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the local paper library, lawful full-text acquisition,
content-addressed PDF storage, PDF.js reading workspace, page-level text/OCR,
annotations, and reviewable cross-version annotation migration.

**Architecture:** Keep `Work` as the only paper identity and extend the existing
`DocumentVersion` and `LibraryState` boundaries. A new `paper_reader.reader`
domain owns imports, storage, acquisition, extraction, OCR, reading position,
annotations, and migration; long operations use the existing durable `Job`
state machine. The SPA receives PDFs only through authenticated document-ID
routes and never receives local filesystem paths.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2, Alembic,
SQLite, PyMuPDF, optional RapidOCR/ONNX Runtime, Vue 3, TypeScript, PDF.js,
Vitest, Playwright, pytest.

## Global Constraints

- Windows 11 x64 remains the only v1.0 target; no Python or Node.js is required
  by end users after packaging.
- Full text is acquired only after open, save, manual import, or analysis intent.
- Only lawful open-access URLs or user-provided files are accepted; no paywall
  bypass and no real restricted paper in test fixtures.
- File processing rejects traversal, non-PDF data, oversized input, and unsafe
  network destinations, and responds to durable job cancellation.
- SHA-256 is the file identity. Physical files are content-addressed under the
  configured library root, while API responses expose only opaque IDs.
- Cache cleanup removes bytes but retains paper metadata, feedback, and audit
  records. Favorite, pinned, analyzed, or annotated content is protected.
- Normal text pages never require or download OCR models. OCR is page-scoped,
  optional, and visibly degraded when its runtime is unavailable.
- Annotation migration never edits or deletes the source annotation. Every
  candidate requires an explicit accept or reject decision.
- New production behavior follows RED -> GREEN -> REFACTOR and commits use
  `feat(reader): ...`.
- Python core-domain branch coverage stays at or above 90%; total line coverage
  stays at or above 80%; UI remains WCAG AA.

- `src/paper_reader/reader/models.py`: reader-only persistence records.
- `src/paper_reader/reader/storage.py`: safe content-addressed byte storage.
- `src/paper_reader/reader/imports.py`: PDF, DOI, BibTeX, and URL normalization.
- `src/paper_reader/reader/acquisition.py`: allowlisted streamed HTTP download.
- `src/paper_reader/reader/retention.py`: protected-content and 90-day cleanup.
- `src/paper_reader/reader/extraction.py`: PyMuPDF page extraction and errors.
- `src/paper_reader/reader/ocr.py`: scanned-page detection and optional OCR.
- `src/paper_reader/reader/annotations.py`: positions, annotations, migrations.
- `src/paper_reader/reader/repository.py`: library/document read models.
- `src/paper_reader/reader/api.py`: `/api/v1/library` and `/api/v1/documents`.
- `src/paper_reader/reader/workers.py`: durable acquisition/extraction workers.
- `web/src/pages/LibraryPage.vue`: saved-paper library and import entry points.
- `web/src/pages/ReaderWorkspacePage.vue`: adaptive three-column workspace.
- `web/src/components/PdfReader.vue`: PDF.js rendering and reader controls.
- `web/src/components/AnnotationPanel.vue`: notes, highlights, bookmarks, migration.

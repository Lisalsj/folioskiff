# v0.5 Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:executing-plans` to implement this plan task-by-task. The
> repository owner selected single-primary-agent execution, so do not dispatch
> subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver click-to-run Codex/Ollama paper analysis, immutable and
reproducible reports, one durable conversation per Work, and versioned
multi-paper comparison without allowing Agent output to influence paper scores,
ranking, or feedback.

**Architecture:** Add a `paper_reader.agents` application domain behind a small
`AgentBackend` protocol. The domain assembles an immutable evidence bundle from
one exact `DocumentVersion`, runs a backend only from an explicit user command,
validates every result with Pydantic, and persists structured fragments before
publishing SSE events. Codex runs as a child process in a fresh read-only task
directory; Ollama uses injected HTTP clients. Reports, conversations, and
comparisons own separate append-only tables and reference evidence hashes.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2, Alembic,
SQLite, `asyncio.create_subprocess_exec`, HTTPX, Codex CLI, Ollama REST API,
Vue 3, TypeScript, Vitest, Playwright, pytest.

## Global constraints

- A model is never invoked by page load, plan execution, scoring, saving,
  opening a PDF, or fetching a preflight. Only an authenticated mutation made
  by the user may create an Agent Job.
- `AgentBackend` can read the selected evidence but cannot import or receive a
  score repository, ranking service, preference repository, source credential,
  local path outside its task directory, or database session.
- Codex reuses its own login state. The application does not read, copy, export,
  or modify Codex credentials or `~/.codex/config.toml`.
- Every Codex invocation explicitly supplies a legal reasoning effort, service
  tier, `approval_policy=never`, read-only sandbox, disabled web search unless
  opted in, no notifications/hooks/project instructions, disabled shell,
  multi-agent, plugin, app, image-generation, and JavaScript tools, and a
  command-line disable override for every MCP server returned by `codex mcp
  list --json`. Empty `mcp_servers={}` is not considered isolation because
  Codex merges that table with inherited configuration.
- Child processes use `create_subprocess_exec`, never a shell. Their environment
  is allowlisted and excludes application/source API keys. Timeouts and Job
  cancellation terminate the complete process tree on Windows.
- Codex task directories live under `AppPaths.cache_root / "agent-jobs"`,
  contain only application-created evidence/schema/output files, and are
  removed after success or reduced to a redacted diagnostic after failure.
- Ollama Local uses `http://127.0.0.1:11434/api` by default and no credential.
  Ollama Cloud uses `https://ollama.com/api` and an OS credential-vault key.
  URLs are fixed built-ins in v0.5 rather than arbitrary SSRF-capable settings.
- Model IDs are dynamically discovered. A failed discovery exposes a manual
  model-ID input and, for Codex, a “use Codex default” choice; production code
  never hardcodes a model catalog.
- Local Ollama structured output uses the `format` JSON schema. Ollama Cloud is
  parsed and validated, then receives exactly one repair request when invalid.
- Prompt templates and final reports are immutable versions. The exact composed
  prompt, evidence manifest, document content hash, backend, model, reasoning,
  service tier, language, network policy, timestamps, and external citations
  are retained for reproducibility.
- Paper text, annotations, and prior model output are untrusted data. Delimiters
  and the system instruction explicitly prohibit following embedded commands.
  External research sources are stored separately from paper evidence.
- Formal reports distinguish author claims from Agent judgments and cite page,
  figure, table, formula, annotation, or external-source evidence.
- Failed validation creates a diagnostic draft, never a formal report. A new
  report version never overwrites an old version.
- Conversation messages and comparison evidence are append-only. Compression
  creates visible checkpoints but never deletes original messages.
- Normal production work follows RED -> GREEN -> REFACTOR. Commits use
  `feat(agent): ...`; documentation and generated OpenAPI stay synchronized.

## Fixed public contracts

```python
class AgentBackend(Protocol):
    @property
    def capability(self) -> AgentCapability: ...
    async def discover_models(self) -> ModelCatalog: ...
    async def generate(
        self,
        request: AgentRequest,
        *,
        on_fragment: Callable[[AgentFragment], Awaitable[None]],
        cancelled: Callable[[], bool],
    ) -> AgentResult: ...

class AgentTaskKind(StrEnum):
    KEYWORDS = "keywords"
    REPORT = "report"
    CHAT = "chat"
    COMPARISON = "comparison"

class ReasoningEffort(StrEnum):
    MINIMAL = "minimal"
    LOW = "low"
    MEDIUM = "medium"
    HIGH = "high"
    XHIGH = "xhigh"

class EvidenceLevel(StrEnum):
    FULL_TEXT = "full_text"
    ABSTRACT_ONLY = "abstract_only"
```

Backend IDs are `codex_cli`, `ollama_local`, and `ollama_cloud`. The default
reasoning efforts are keywords `medium`, report `high`, chat `medium`, and
comparison `high`. Supported report languages are `zh-CN`, `en`, and
`bilingual`.

The public API groups are:

- `GET /api/v1/settings/agents`
- `PUT|DELETE /api/v1/settings/agents/ollama-cloud/credential`
- `GET /api/v1/analysis/templates`
- `POST /api/v1/analysis/templates`
- `POST /api/v1/analysis/preflight`
- `POST /api/v1/analysis/reports`
- `GET /api/v1/analysis/reports/{report_id}`
- `GET /api/v1/analysis/reports/{report_id}.{format}`
- `GET /api/v1/works/{work_id}/analysis/reports`
- `GET /api/v1/works/{work_id}/conversation`
- `POST /api/v1/works/{work_id}/conversation/messages`
- `GET /api/v1/comparisons`
- `POST /api/v1/comparisons`
- `GET /api/v1/comparisons/{comparison_id}`

Agent commands return HTTP 202 and an existing `JobDetail`; an identical
`Idempotency-Key` returns the original Job. Stream event types include
`analysis.delta`, `conversation.delta`, `comparison.paper`, and
`comparison.delta`; the fragment row is committed before the Job event.

## Exit criteria

- Loading any page, reading a PDF, or scoring recommendations performs zero
  Agent calls; an explicit click creates the only model invocation path.
- Codex and Ollama expose dynamic model choices with a truthful manual fallback.
- The exact current paper version and evidence level are visible before a run
  and immutable in every formal report.
- Structured failures retain a useful redacted draft and never replace a prior
  valid report.
- Reports separate author claims, Agent judgments, paper evidence, and optional
  external evidence; citations resolve to recorded manifests.
- Original conversation messages remain available after compression.
- Comparisons disclose per-paper evidence coverage and use staged synthesis over
  ten papers.
- Agent operations cannot call inherited Codex tools, escape their evidence
  directory, change scoring/ranking/feedback, or expose credentials.

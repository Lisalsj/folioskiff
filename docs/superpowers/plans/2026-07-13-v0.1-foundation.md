# v0.1 Foundation TDD 计划

## 目标

在一个可审查提交序列中完成旧运行时到可启动新骨架的原子切换。主分支不能出现“旧系统已删、新系统不能启动”的状态。

## 任务

1. **身份与目录**
   - Red：断言项目/npm/CLI 为 `paper-reader`，包为 `paper_reader`，状态/缓存/论文库分离。
   - Green：实现包身份、`AppPaths` 与目录创建。
   - Verify：Windows 路径、覆盖参数、无旧名称运行引用。
   - Commit：`feat: establish paper reader backend foundation`。
2. **SQLite 与 Job**
   - Red：WAL、外键、Alembic head、幂等 Job、取消请求。
   - Green：SQLAlchemy、`0001_foundation`、Repository。
   - Verify：重复升级、崩溃后记录仍在、并发基础检查。
3. **本地 HTTP 安全**
   - Red：健康检查、未授权 401、bootstrap 单次使用、CSRF/Origin 拒绝。
   - Green：动态回环 socket、HttpOnly 会话、双提交 CSRF、API 404。
   - Verify：secret 不进入请求路径/日志，非回环拒绝。
4. **Vue 应用壳层**
   - Red：六个主入口、路由激活、启动 secret 清除与交换。
   - Green：Vue/Router/Pinia、安静图书馆 token、响应式导航。
   - Verify：Vitest、typecheck、build、浅深色、390/1024/1440 视口。
5. **任务事件与 OpenAPI**
   - Red：HTTP 202 幂等命令、递增事件序列、`Last-Event-ID` 恢复、轮询回退。
   - Green：Job event 表、SSE endpoint、前端任务 store/drawer。
   - Verify：先持久化后发送、取消反馈、断线重连。
6. **原子清理与工程化**
   - Red：结构测试拒绝旧包、VitePress、archive 和旧命名。
   - Green：删除旧运行时，写 README/docs/CI/LICENSE/日志脱敏/锁文件。
   - Verify：pytest/Ruff/MyPy/Vitest/typecheck/build/audit/axe，源码安装后可启动。

## 退出条件

所有 v0.1 自动检查通过；安装依赖并构建前端后，`paper-reader serve` 可打开 SPA、建立安全会话、读取任务；旧运行时已完全删除；文档能力矩阵不虚报。

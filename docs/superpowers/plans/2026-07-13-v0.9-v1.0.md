# v0.9 RC / v1.0 TDD 计划

## 目标

冻结 API/schema/插件协议，完成跨功能、安全、性能、无障碍与干净机器验收，修复全部阻断项后发布 v1.0。

## 任务

1. 运行完整 Python/前端/E2E/fixture/live-smoke（有密钥）矩阵，建立阻断清单；每个缺陷先加入最小回归测试。
2. 做迁移链、崩溃恢复、备份恢复、重复导入、模糊去重、内容哈希和标注迁移故障注入。
3. 做回环会话、CSRF、路径、日志、凭据、插件越权、恶意 PDF、提示注入和发布白名单安全审计。
4. 在 20 万元数据和目标硬件测冷启动、p95 列表/检索、PDF 首屏、取消；先保存基线，再针对瓶颈优化并防回归。
5. 运行 axe、完整键盘、200% 缩放、屏幕阅读器抽查、深色/高对比/降动画和三种视口。
6. 在干净 Windows 11 VM 完成安装、首次运行、升级、卸载、便携、离线降级和模型下载。
7. 冻结数据库 schema、OpenAPI v1、插件协议 1.x；生成最终迁移兼容报告与 SBOM。
8. 更新 CHANGELOG、README 能力矩阵、已知限制、隐私说明和 Release Notes；生成 SHA-256。
9. 发布 v1.0 tag/Release，验证安装资产；最后将本地目录改名为 `paper-reader` 并提示重新打开工作区。

任何阻断失败都必须回到 Red → Green → 全量验证；不允许以“已知问题”绕过核心验收。提交使用 `fix(rc): ...`、`docs(release): ...`，最终发布由独立 release commit/tag 完成。

## 退出条件

所有计划中的关键验收和性能阈值有可复查证据，0 个阻断项，发行物可安装，文档与实际能力一致。此时才可将持续目标标记完成。

# UI/UX 与“安静图书馆”规范

## 1. 信息架构

桌面主导航固定为：阅读简报、关注计划、我的论文库、多论文比较、精选发布、设置。640px 以下保留“简报、计划、论文库、更多”四个带文字的底部入口；比较、发布、设置与脱敏诊断进入 More 对话框。首页聚合 Agent 阅读简报、关注计划状态、新论文、重要修订和待继续任务，不提供占据视觉中心的通用搜索框。

新建计划严格遵循：研究意图 → 关键词工作台 → 月份/来源 → 来源预览 → 保存/运行。每一步保留草稿；只有关键词确认、预览完成后才可运行。

当前 Discovery 工作流已实现为真实四步向导：研究意图只生成建议；关键词按必需/增强/排除概念组编辑并生成不可变确认版本；月份页同时设置固定或滚动自然月、来源特有过滤器与手动/每日/每周/每月频率；预览页展示逐来源估量、关键词裁剪漏斗、样例和日期语义警告。超过 24 个月只警告、不禁止。禁用来源直接显示缺密钥状态并引导到设置页，不伪装成可用来源。

关注计划页同时承担运行入口、应用关闭期间的确认补跑和模糊重复论文人工审阅。重复论文采用双列身份证据比较，默认建议“不确定时保持分开”；只有明确决定才离开队列。设置页把“五个论文来源”和“三个质量证据服务”分成两个层级区块。来源/增强器密钥使用密码输入，Crossref 联系邮箱使用邮箱输入；保存后立即清空，界面只显示“已安全配置/需要配置/可选”。

### 1.1 首次配置

首次启动不显示全局侧栏，使用“存储与隐私 → AI 能力 → 论文来源 → 阅读偏好”四步向导。存储与隐私是唯一必需步骤，其余步骤持续显示“稍后配置”。用户可以返回已完成步骤检查或修正设置，但未确认的当前步骤不会被界面假定为已完成。

- 存储步骤显示状态、缓存、论文库和备份的真实解析路径；只允许修改缓存与论文库，并在变更时先持久化步骤状态，再发起受控重启。
- AI 步骤只执行能力探测，不生成内容。Codex CLI 明确说明本地命令行与模型云端运行是不同边界，诊断码、版本和模型列表只展示安全探测结果。
- 来源步骤把可直接使用的免费来源与可选凭据分开；密钥字段不回显，提交结束后无论成功或失败都立即清空。
- 阅读偏好默认中文报告、英文到中文翻译、Codex CLI、中等推理强度、跟随系统主题和时区。扩展偏好由统一设置契约持久化，不在组件内伪造已保存状态。

桌面进度条横向呈现，窄屏改为纵向列表。步骤进度属于具名导航地标，活动标题在步骤切换后获得程序化焦点；所有视口都保留清楚的加载、重试和稳定错误文案。

### 1.2 分区设置

`/settings` 是稳定入口并重定向到 `/settings/overview`。设置使用“配置总览、AI 与模型、论文来源、阅读与语言、推荐与评分、存储与备份、扩展与发布、关于与更新”八个子路由；每个子路由独立懒加载，也只读取当前分区的数据。桌面使用具名侧边导航，760px 以下切换为原生分类选择器，避免在窄屏重复展示两套导航。

配置总览只展示可操作的本地事实：目录可写性、Agent 与来源就绪数量、词法/语义检索模式、最近备份和更新状态。每条待处理事项都链接到精确分区及能力锚点；缺失模型、凭据或外部服务不会伪装成阻断整个阅读闭环。

子表单通过共享的多来源脏状态登记未保存修改。任一表单仍有修改时，跨设置分区或离开设置才显示一次原生确认；保存一个表单不会错误地清除其他表单的保护。分区切换后焦点移动到新的二级标题，普通查询参数变化不触发离开提示。

来源与质量证据服务位于“论文来源”，质量规则和合法本地评级目录位于“推荐与评分”，不再由一个巨石页面同时请求。关于页集中版本、开源许可、更新和手动诊断导出；脱敏诊断摘要采用字段白名单，只包含版本、冻结契约、目录可写性与能力状态，不包含实际目录、凭据、论文、笔记、聊天、偏好或日志，也不会自动上传。

“AI 与模型”把只读能力事实与用户默认值分开：后端卡片显示稳定诊断码、安全版本、本机/云端位置和可恢复建议；默认值表单统一保存后端、可选模型、推理强度、报告语言及翻译方向，保存或刷新都不会生成内容。Ollama Cloud 密钥只进入系统凭据库，提交结束即清空输入且从不回显；Codex CLI 虽由本机命令启动，使用外部模型时仍持续标注为云端处理。

阅读工作台桌面为三栏：左侧论文与版本、中间 PDF、右侧阅读助手；右侧“批注”“分析报告”和“论文助理”彼此独立，论文助理内部提供提问、解释和翻译三种明确模式。中等宽度把论文与版本收进有遮罩、可明确关闭的抽屉；移动端直接在 PDF/批注/报告/助理四个标签间切换。PDF 面板只通过 CSS 隐藏而不卸载，因此切换后保留当前页、缩放、旋转、搜索和文本选择状态。固定任务按钮占用顶栏最右侧的保留空间，不遮挡页码。

“我的论文库”已接入真实本地读模型：按标题、作者或 DOI 筛选，逐行显示作者、日期、版本数、代表文件、阅读进度与可读状态。只有 `representative_document.available=true` 才出现“阅读”链接；只有元数据或受限版本明确显示“暂无可读 PDF”，不会伪造下载入口。列表具有加载、空库、无匹配、失败重试和分页状态，并提供“导入论文”与逐 Work“添加版本”入口。

## 2. 视觉语言

- 气质：安静、编辑化、研究密度高，不做营销落地页。
- 交互强调色只使用深森林绿；酒红只用于撤稿、重大更正等危险语义。
- 浅色采用暖纸色背景、深墨正文、低对比线条；深色是独立配色，不直接反色。
- 出版语境的一级、二级标题可用 Georgia/宋体衬线；界面正文使用 Segoe UI Variable/微软雅黑无衬线。
- 圆角统一为 8–10px；不用大面积胶囊、渐变、玻璃、发光、漂浮装饰或同权重卡片墙。
- 数据密集区以分隔线、层级、列对齐和留白组织，避免无意义容器嵌套。
- 主题是关闭式用户偏好：跟随系统、浅色、深色三种。浏览器只在 `paper-reader.theme` 缓存这一枚非敏感显示值，并在 Vue 挂载前应用；服务端事实到达后立即校准。深色使用独立森林绿/暖墨配色，不能靠全页反色实现。

## 3. 关键组件

- `IntentComposer`：研究意图输入、领域/语言提示、Agent/本地回退状态。
- `KeywordWorkbench`：概念组、同义词 OR、必需组 AND、增强、排除、差异和确认。
- `SourcePreview`：每来源估量、5–10 条样例、关键词影响、密钥/限流状态。
- `PaperRow`：题名、作者、日期、来源、四类分数、证据覆盖和危险提示。
- `ScoreEvidencePanel`：公式、原始证据、缺失/不适用、规则版本。
- `ScoreRuleEditor`：七维启用状态、总计 100% 的数字权重、不可变修订名称、默认恢复和服务端无证据解释预览；停用状态不能依赖低对比度透明效果。
- `AnalysisPreflight`：后端、模型、推理、语言、模板、证据等级、联网和范围。
- `ComparisonWorkspace`：从本地论文库多选并显式调整顺序；选择 2–10 篇时预告一次综合，11 篇以上在调用前解释逐篇提取、每批最多 10 篇与最终汇总。后端与模型优先使用能力探测结果，探测失败仍允许手填模型 ID。预检逐篇显示全文/摘要/不可用证据和覆盖率，云端后端持续可见；只有点击生成才创建 Job。运行中显示逐篇处理数与总体进度，不设前端人为超时，离页后保留恢复指针；结果区同时保留逐篇覆盖、版本历史和 Markdown 导出。
- `JobDrawer`：所有长任务的进度、取消、重试、摘要日志和失败分类；`translation.generate` 必须显示为“翻译论文”，不暴露内部任务名。
- `SavedLibrary`：本地 Work 列表、搜索、版本/进度摘要和只指向合法代表 PDF 的阅读入口；导入成功后从服务端重读列表，不在客户端伪造论文行。
- `LibraryImportPanel`：使用 Reka UI Dialog 提供“PDF”与“DOI/BibTeX/URL 引用”两类路径。PDF 必须勾选合法取得并在客户端先检查 100 MiB/文件类型，服务端仍做最终校验；引用路径明确提示不会下载正文。对既有 Work 打开时只允许添加 PDF 版本，避免把引用误绑定成新版本。
- `ReaderWorkspace`：桌面三栏、中等宽度版本抽屉、移动端 PDF/批注/报告/助理持久面板，以及不与全局任务按钮冲突的紧凑论文顶栏；打开版本时恢复其页码、缩放和旋转，700ms 合并保存变化并在页面隐藏/离开前尽力刷新。
- `QuickTranslationPanel`：只在用户切换到翻译模式后展示语言方向、当前证据范围、Agent/模型和本地资料边界；挂载与切换模式都不调用模型，只有“开始翻译”创建持久任务。已完成选区译文可由用户明确放入后续提问草稿，不能自动进入聊天。
- `BilingualReader`：独立懒加载路由按 PDF 页分批呈现不可变 segment ID 对齐的原文与译文，支持对照/原文/译文三种模式；页码、段落和模式写入 URL 查询以便刷新恢复。OCR 置信度、部分失败诊断、取消/继续、术语过期和导出边界始终可见；长论文只渲染当前页段落，不把整篇译文一次性挂入 DOM。
- `PdfReader`：按路由惰性加载同版本 PDF.js 与 bundled worker；仅呈现当前页以避免非可见页画布占用，取消被翻页/缩放取代的旧画布和文本层任务。支持同源 cookie、HTTP byte range、白色 PDF 页面、可选择文本层、全文页面检索、直接页码、缩放、旋转和适合宽度；把 DOM 文字选择转换为未旋转 PDF point 坐标，显示随旋转/缩放对齐的批注覆盖层，并提供本页书签与 `Shift+H` 快速高亮。异常大页面的 backing canvas 限制为 25,000,000 像素。
- `AnnotationPanel`：显示当前精确引用和上下文，创建高亮、带笔记引用或页书签；按类型筛选并支持定位、改色、编辑笔记和确认删除。保存/失败/空状态通过 `aria-live` 宣告，操作后恢复焦点，高对比度模式不依赖颜色表达选中状态。
- `AnnotationMigrationReview`：从同一 Work 的旧版本选择来源，显示可迁移/歧义/未定位/已处理覆盖度；每次只审阅一个候选，可先在 PDF 上查看临时覆盖层，再明确接受或拒绝。接受只创建新版批注，源批注继续保留。
- `ReaderStorageSettings`：把 OCR 与全文缓存放在同一“本地阅读能力”区。OCR 不可用时仍说明普通文本 PDF 可读，并在下载按钮前展示模型体积与许可；清理必须先列出可删除和受保护对象及原因，之后才出现带数量的执行按钮。
- `MergeReviewQueue`：并排显示候选/既有 Work、题名作者 DOI 与相似证据，提供带备注的合并或保持分开决定。
- `SourceCredentialSettings`：显示五来源能力与官方链接，密钥只写 Windows 凭据库且永不回显。
- `EnricherCredentialSettings`：显示 OpenAlex/Semantic Scholar/Crossref 的用途、协议版本、节流策略和逐项凭据状态；来源获取与质量证据不混为同一列表。
- `GeneralSettings`：并列呈现自然月时区和界面主题。跟随系统时显示当前真实解析值；解析失败明确说明回退 `Asia/Shanghai` 并允许改用合法 IANA 名称。保存后提示“只影响新计划”，计划向导显示当前模式、解析值和冻结语义，不把 `Asia/Shanghai` 硬编码成所有用户的默认事实。

组件优先使用 Reka UI 无样式可访问原语，再应用项目 token。图标只用 Phosphor；每个纯图标按钮必须有可访问名称和 tooltip。

## 4. 状态与文案

必须区分空状态、首次使用、加载、部分成功、无结果、离线降级、缺密钥、权限受限和失败。禁止用虚构统计填充空页面。所有危险或云端操作先说明影响；Codex/Ollama Cloud 始终明显标注外部处理，但分析按钮本身就是用户授权，不再弹第二次私有论文确认。

## 5. 无障碍与响应式

- WCAG AA 对比度，完整键盘路径，焦点可见，动态状态用 `aria-live`。
- 主壳层的首个键盘目标是“跳到主要内容”。切换路由后，焦点移到唯一的 `main`，文档标题随当前界面语言更新。用户可在首次配置、导航或阅读设置中切换中文和英文，论文原文和正在输入的内容保留。
- 所有 Dialog、Tabs、Popover、Select 和 Tooltip 使用可访问原语。
- 阅读器桌面 Agent 使用 Reka UI Tabs 的自动方向键激活；移动 PDF/批注/报告/聊天使用单选 ToggleGroup 的 roving focus，避免四个面板入口全部进入 Tab 顺序。
- 支持高对比度与 `prefers-reduced-motion`；关键状态不能只用颜色。
- PDF 页面永不随深色模式反色；阅读器周边控件使用深色 token。
- 所有强调按钮使用 `--color-on-accent`，使浅色主题的深森林绿与深色主题的浅森林绿分别取得合适前景色；禁止在可换肤组件中硬编码白字。
- PDF 阅读器快捷键：`ArrowLeft/PageUp` 上一页，`ArrowRight/PageDown` 下一页，`+/-` 缩放，`0` 适合宽度，`R` 顺时针旋转，`Ctrl/Command+F` 聚焦全文搜索，选中文字后 `Shift+H` 快速高亮。输入框获得焦点时不会截获其翻页按键。
- 320px 起可用，640px 以下使用四入口底部主导航；每个入口同时显示图标和短文字。More 面板关闭后焦点返回触发按钮，并通过安全区内边距避让系统手势区与阅读器控件。
- 主导航目标在所有持续测试视口均至少 24×24 CSS px；200% 文本重排不得产生页面级水平滚动，固定底部导航不得完全遮住键盘焦点。

## 6. 设计验收

每个里程碑至少检查 1440×900、1024×768、390×844 三种视口；运行 axe、键盘走查、缩放 200%、浅深色与降低动画。视觉截图只作为回归证据，不替代可访问性断言。

首次配置 Task 3 已使用隔离本地资料在 1440×900 与 412×915 真实 Chromium 中走通四步。桌面和移动来源步骤的 axe 结果为零违规；检查中发现并修复了进度列表游离于页面地标之外的问题。视觉复核确认暖纸色、森林绿主操作、酒红诊断、路径表单、能力卡和窄屏单列布局没有裁切或页面级水平滚动。

设置 Task 4 使用独立本地资料走完首次配置后，在 1440×900 和 412×915 的真实 Chromium 中验证总览、来源、Agent 与移动分类选择器。两个视口及来源页的 axe 结果均为零违规；活动分区标题获得焦点，未打开分区不发起请求，移动端滚到文档底部后最后一项完整位于固定主导航上方。

设置 Task 5 在 1440×900 桌面 Chromium 与 Pixel 7 视口复核“AI 与模型”：默认值、三类后端、精确诊断码、版本、本机/云端标识和 Ollama Cloud 凭据边界均完整可见；页面无水平溢出，两个视口 axe 均为零违规。检查只使用拦截的只读能力事实，没有保存真实凭据或调用模型。

设置 Task 6 使用无密钥值的关闭式夹具，在 1440×900、900×900 与 Pixel 7 三个 Chromium 项目走通首次配置和响应式设置。新用户跳过 Agent 与付费来源后仍可完成设置；四个向导步骤、配置总览、Agent 页和移动 More 面板均执行 axe。最终完整 Playwright 回归为 73 项通过、2 项按设计仅桌面执行而跳过；移动视觉复核确认四入口底栏、More 面板、长设置页和安全区避让没有水平溢出或不可达控件。

Reader Task 7 使用真实双页 PDF 而非画布替身完成桌面 Chromium 1440×900 与 Pixel 7 浏览器验收：worker 加载、首屏画布、文本层搜索、翻页、旋转、适宽、移动端 PDF/报告/聊天切换与页码保持均通过，两个视口的 axe 结果为零违规。组件层另以可注入会话验证加载/空/错误状态、直接页码、键盘焦点和资源释放。

Reader Task 8 在同一真实 PDF.js 浏览器链路中以 DOM Range 选择正文，验证精确引用、坐标换算、高亮创建与页面覆盖层；翻到第二页后验证阅读位置合并保存，移动端验证 PDF/批注/报告/聊天切换。桌面与移动视口的 axe 结果均为零违规；单元测试另覆盖四种旋转变换、失败后重试、书签、筛选、编辑、删除、焦点返回与高对比度样式。

## 7. 应用更新设置

“设置 → 关于 → 应用更新”展示当前版本、本地缓存状态和上次检查时间。点击“立即检查”后才联系 GitHub，按钮在等待结果时显示“正在检查…”。

有效 Release 使用三层信息：顶部版本/日期，中央状态与未签名警告，随后并列的变更和迁移说明以及紧凑能力标签。移动端把版本与说明自然折为单列，不隐藏未签名信息；200% 字号不产生水平滚动。离线、限流、服务不可用和安全校验失败都使用可恢复文案，不制造“必须立刻升级”的紧迫感。

只有确认存在更高正式版本且固定 GitHub URL 再次通过前端校验时，才显示“查看并更新”。点击后使用焦点受控的 AlertDialog 明确说明将离开应用、不会自动下载、执行或重启，并再次列出版本、签名与目标仓库；确认后新标签页采用 `noopener,noreferrer`。跨 host 或畸形链接只显示警告，不渲染可点击入口。

## 8. v2 阅读体验冻结

首次配置使用四个短步骤和持续可见的能力摘要，不用一次性长表单。阅读器进入**沉浸式阅读工作台**后，桌面保持论文导航、PDF、Assistant 三栏；中等宽度把论文导航收进抽屉，移动端把 PDF 与 Assistant 变成保留阅读位置的标签。

Assistant 的一级意图固定为**提问、解释、翻译、相关推荐**，所选证据、网络范围和发送动作必须同屏可见。英译中不引入额外联网确认；相关知识网站则在执行前使用明确的同意控件。

视觉基线覆盖桌面 `1440×900`、中等 `900×900` 和 `Pixel 7` 三种视口，浅色/深色/跟随系统、降低动画、高对比度、键盘导航与 200% 字号都不得出现页面级横向滚动。PDF 页面保持纸面本色，不随主题反色。

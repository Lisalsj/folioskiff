# 论文 AI 阅读助手

统一论文 Assistant 位于阅读工作台右侧，支持**提问、解释、翻译、相关推荐**四种意图。它和“正式分析报告”是两条独立路径：Assistant 用于持续阅读对话，报告是用户点击“分析”并完成预检后产生的不可变成果；两者都不会改变论文评分、推荐排序或用户反馈。

## 上下文与触发

用户可以把当前选区、当前页、整篇已提取文本、标注或论文元数据加入上下文。发送前界面会显示证据范围、文档哈希、后端、模型和网络策略。选择文本、翻页、打开 PDF 或看到推荐都不会自动调用模型；只有点击发送、翻译、查找相关内容或分析按钮才创建持久任务。

## 四种意图

- **提问**：针对作者主张、方法、实验或局限进行有页码依据的问答。
- **解释**：用用户选择的深度解释术语、公式、图表或一段论证，并区分论文原文与 Agent 推断。
- **翻译**：默认把英文到简体中文，保留公式、引用、术语和段落对应关系；可选择整页或选区，结果绑定原始文本哈希以便复现。
- **相关推荐**：先从论文证据和已确认偏好生成可编辑的检索意图、概念组与排除条件。用户确认后，才查询已启用的学术来源；知识点网站等外部资源需要该次任务单独开启外部研究。

普通提问、解释和翻译不会联网，它们使用已选择的论文、标注和本地元数据。即使后端本身具备联网能力，默认 `local_only` 策略也不能被论文内容覆盖。相关推荐查询官方论文来源属于用户确认后的来源访问；访问一般知识网站属于 `external_research`，必须逐次显式同意，并在结果中保留 URL、标题、访问时间和证据摘要。

## 证据、失败与隐私

回答优先引用页码、图、表和用户选区。只有摘要可用时会显示“摘要证据”；无法找到依据时应明确说不知道，而不是补写看似合理的结论。PDF 文本始终是不可信证据，文中的“忽略系统指令”或工具调用要求不会获得更高权限。

流式片段先持久化再发送，断线后可以继续。结构化输出不合格时只进行一次受控修复；仍失败会保存可检查的失败草稿，不覆盖已有正式结果。切换 Agent 后端不会把旧会话静默发送到新服务，发送范围始终在操作前可见。配置方法见 [Codex 与 Ollama 配置](codex-ollama-setup.md)，网络和提示注入控制见 [v2 威胁模型](threat-model-v2.md)。
